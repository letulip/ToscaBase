The XML engine ships standard Modules that open (or create) an XML file and verify nodes in it by XPath. For richer work, **File Scan** turns an XML file into a Module whose ModuleAttributes are the XML nodes, so you can use every ActionMode on them: verify, constrain a search, buffer a value. This page covers both approaches, plus a worked example that reads an ISBN out of XML generated by a web page.

## Verify a node with the standard Modules

Two Modules from the XML engine are enough for a plain verification. Search the Modules for `XML` and add both to a TestCase:

1. **Open/Create XML File** opens an existing file, or creates a new one. Fill in:
   - **Resource**: a name of your choice for the opened document, for example `BooksXML`. Every later XML TestStep refers to the file by this name.
   - **File path**: the full path of the XML file.
2. **Verify XML** checks one node:
   - **Resource**: the same name you used when opening.
   - **XPath**: the path of the node inside the XML tree.
   - **Value**: the expected value. Wildcards are allowed, so `Microsoft*` verifies a title that starts with "Microsoft" without spelling out the rest.

On execution the log lists every step; for the XPath step it reports that the verification was successful, together with the expression and the actual value.

### Writing the XPath

Any node you want to reach needs its path in the tree. Write it yourself or generate it with a tool; the video uses the browser:

1. Open the XML file in the browser, right-click and choose **Inspect**. The tree of nodes appears.
2. Press **Ctrl+F** in the inspector. The find box accepts XPath and highlights the matches, so you can test the expression before pasting it into Tosca.
3. Narrow the expression step by step: `book` matches every `book` node, `book[@id="bk110"]` keeps only the book with that id, and `book[@id="bk110"]/title` selects its title.

:::caution
XPath contains characters that Tosca treats as special. Right-click the value and choose **Escape value**, otherwise execution throws errors. The string inside the predicate needs extra care: the speaker doubles the quotes around the id (one pair for XPath, one pair so Tosca reads it as a string).
:::

:::note
The book id is auto-transcribed as "pk110"; in the well-known `books.xml` sample the ids read `bk101`, `bk102` and so on. Take the exact id from your own file.
:::

## Scan an XML file into a Module

Instead of typing XPath expressions you can let Tosca build a Module from the file:

1. In **Modules**, choose **Scan > More > File Scan**.
2. Browse to the XML file. Tosca creates a Module named after it (Tosca 16 adds the suffix `Request`: `books Request`, `catalog Request`); rename it (for example `BooksXML`).
3. The Module contains a `Resource` attribute and one ModuleAttribute per node of the file (for `books.xml`: the catalog, each book, its title, ISBN and so on).

Before you use this Module in a TestCase, the file must be opened with **Open XML** (the same open Module as above) and the `Resource` value of both TestSteps must match. Leave it empty on the scanned Module's TestStep and the run fails with *Either a resource or a transition has to be specified* (Lesson 54); fill in the same name and rerun.

## Worked example: find an ISBN in generated XML

Obstacle 12 of the practice site combines several engines. A **Load Books** link fills a disabled text area with XML; the task is to find the ISBN of the book titled *Testing Computer Software* and type it into a text field. Because the text area is disabled, the XML cannot be searched in the browser; it is written to a file and searched there.

Modules needed: the web page (link, text area, text field) scanned with XScan, the standard Modules **TBox Create File** and **Open XML**, and a File-Scan Module of the XML file, all kept in a folder named after the obstacle.

TestSteps, in order:

1. **Load the XML**. Click the `Load Books` link, then set the text area to ActionMode `Buffer` with buffer name `XMLText`.
2. **Write the file**. Add **TBox Create File** (transcribed as "read create file"): the target directory, file name `books.xml`, `Text` = `{B[XMLText]}` and `Override` = `True`, so an existing file is overwritten. Run these two steps once and open the file to confirm the content, then run the file scan described above on it.
3. **Open the file**. Add **Open XML** with resource `Books` and the file path. Drag it above the search step if you added it afterwards.
4. **Search the book**. Add the scanned XML Module with the same resource `Books`. On the `title` node set ActionMode `Constraint` with the value `Testing Computer Software`; the constraint filters the tree down to that book. On the `isbn` node of the same book set ActionMode `Buffer` with buffer name `BookISBN`.
5. **Enter the result**. Add the web Module again and input `{B[BookISBN]}` into the ISBN text field.

Set the Workstate to completed, refresh the page and run the whole TestCase in the ScratchBook: the link is clicked, the XML is buffered and written to `books.xml`, the file is opened and searched, and the ISBN lands in the text field.

:::tip
The pattern "buffer, write to file, scan the file, constrain, buffer" is reusable for any data an application shows only as raw text.
:::

## Worked example: extract two values from a downloaded XML

Obstacle 28 is the simpler cousin of the previous example. A `catalog` link downloads an XML file; each entry under `catalog` has an `id` (the person's name), a `prefix`, a `number` and a `gender`. The task: find the entry named *Sue* and type its prefix followed by its number into a text box.

1. Download the file through the link and note its location in the Downloads folder.
2. **Scan > More > File Scan**, select `catalog.xml`; Tosca creates a Module with the whole node tree. **Scan > Application** the browser and save the text box as a second Module (`Number`).
3. TestCase, first step: **Open/Create XML File** with resource `catalog` and the file path. Without it no node can be read.
4. Second step: the scanned XML Module with resource `catalog`. On the `id` node set ActionMode `Constraint` with `Sue`, so only that entry is selected. On `prefix` set ActionMode `Buffer` with buffer name `pre`, on `number` ActionMode `Buffer` with `num`.
5. Third step: the text-box Module, input `{B[pre]}{B[num]}`. Two buffers written one after the other concatenate the values.

Set the Workstate to completed and run: the text box receives the prefix and number together.

:::note
The node names are as the speaker reads them; take the exact spelling and case from the scanned Module. Lesson 70 calls the scanned tree a "JSON structure"; the file is XML.
:::
