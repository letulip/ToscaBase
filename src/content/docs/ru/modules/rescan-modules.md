Первое сканирование страницы редко получается правильным для всех контролов. Часть из них Tosca идентифицирует уникально, часть оставляет неоднозначными, и вы узнаёте об этом, только когда TestStep падает с ошибкой *more than one control found*. Rescan (пересканирование) заново открывает существующий Module в XScan поверх живого приложения, так что можно добавить технические свойства, сменить метод идентификации или добавить пропущенные контролы, не создавая второй Module для той же страницы. Это же инструмент на случай, когда приложение изменилось и контрол больше не находится.

## Когда пересканировать

- TestStep падает, потому что нашлось больше одного контрола. В источнике это радиокнопка: на странице две радиокнопки с одинаковыми техническими свойствами, и Tosca не может решить, какую нажать.
- Контрол на странице изменился, и Module его больше не находит.
- Новому TestCase нужен контрол, который не был отсканирован. Пересканируйте и добавьте его в существующий Module, а не сканируйте заново; см. [Гигиену Module](/ToscaBase/ru/best-practices/module-hygiene/).

## Процедура

1. Откройте тестируемое приложение на странице, которую описывает Module. Если оно не открыто, Rescan сообщит *no window found*.
2. В секции **Modules** щёлкните Module правой кнопкой и выберите **Rescan**.
3. XScan откроется с уже выбранными контролами Module плюс всеми остальными контролами страницы. Обновите, если страница ещё не показана.
4. Выделите проблемный контрол. Оранжевая полоса и сообщение *selected item is not unique* внизу подтверждают проблему. Показаны отмеченные сейчас технические свойства; в источнике были выбраны только `name` и `tag`.
5. Отметьте дополнительное техническое свойство. Выбирайте то, что имеет смысл для идентификации (`id`, `name`, `value`), а не любое отличающееся свойство (`checked`, `disabled`, `readonly` в списке есть, но это состояние, а не идентичность). Отметка `value` делает радиокнопку уникальной, и оранжевая полоса исчезает. Если ни одно свойство не помогает, смените метод идентификации; см. [Идентификацию контролов](/ToscaBase/ru/modules/control-identification/).
6. **Save** и закройте XScan.

## Что Rescan делает с Module

В источнике Rescan не отредактировал существующий атрибут, а **добавил новый атрибут** с дополнительным свойством (`value`) рядом со старым. После этого:

1. Переименуйте новый атрибут, чтобы понимать, в каком из них исправление.
2. Удалите старый атрибут. Tosca предупредит, что он используется в TestStep; подтвердите.
3. Откройте TestCase. TestStepValue, ссылавшийся на удалённый атрибут, сломан; удалите его и добавьте в TestStep новый атрибут с нужным действием.
4. Запустите в ScratchBook. Указатель мыши уходит на правильную радиокнопку, и TestCase проходит.

:::note
Источник не объясняет, когда Rescan обновляет атрибут на месте, а когда добавляет новый; показано только поведение «новый атрибут». После каждого пересканирования проверяйте Module на дублирующиеся атрибуты, прежде чем что-то удалять.
:::

## Rescan или новое сканирование

Новое сканирование создаёт второй Module для той же страницы, а все TestCase, уже использующие первый, продолжают указывать на него. Rescan сохраняет один Module и один набор использований. Если кто-то уже отсканировал вторую копию, объедините их через [Дубликаты и слияние Module](/ToscaBase/ru/modules/duplicate-and-merge-modules/).
