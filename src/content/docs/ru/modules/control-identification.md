Во время выполнения Tosca должна найти каждый контрол на экране по тому, что о нём хранит Module. XScan предлагает четыре метода идентификации, доступных в меню **Identify by** в Advanced view: **properties** (по свойствам), **anchor** (по якорю), **image** (по изображению) и **index** (по индексу). Они образуют иерархию: пробуйте их в этом порядке и останавливайтесь на первом, который делает контрол уникальным. Пятый приём — configuration parameter `ExplicitName` — не метод XScan, а способ выбрать один из нескольких одинаковых контролов из TestCase. Этот документ объясняет методы; разобранные проблемные случаи — в [Препятствиях: идентификация контролов](/ToscaBase/ru/troubleshooting/obstacles-identification/).

Все четыре источника используют один пример: стартовая страница Google, где кнопка *Google Search* неуникальна, потому что вторая, невидимая кнопка имеет ровно те же свойства (`name`, `type`, `value`). Текстовое поле рядом уникально.

## Identify by properties

Метод по умолчанию. Tosca сопоставляет технические свойства, отмеченные в XScan (`id`, `name`, `tag`, `value`, `InnerText`, `alt`, ...). Всегда предпочитайте его: он самый стабильный и самый быстрый.

Когда XScan сообщает *selected item is not unique*, первый ход — отметить больше свойств в Advanced view. Часто хватает одного дополнительного (`alt` для логотипа Google, `value` для радиокнопки в [Пересканировании Module](/ToscaBase/ru/modules/rescan-modules/)). Выбирайте свойства, описывающие идентичность, а не состояние. Если все осмысленные свойства уже отмечены, а контрол всё ещё не уникален, как кнопка *Google Search*, переходите к anchor.

## Identify by anchor

Anchor (якорь) — другой контрол по соседству с целевым, который *уникален*. Tosca сначала находит якорь, а затем цель относительно него. Используйте его только когда свойства не помогли; если рядом нет стабильного, уникально идентифицированного контрола, этот метод не подходит.

1. Выделите целевой контрол и выберите **Identify by > Anchor**. Справа откроется панель **Identify by anchor**.
2. Tosca может попытаться выбрать якорь автоматически. В панели есть настройка режима; источник упоминает значения *Auto*, *Always*, *Shortest path* и *Coordinate* и использует *Auto*, который якорь для кнопки не нашёл.
3. Добавьте якорь сами: перетащите уникальный контрол из дерева в слот якоря (в источнике перетаскивают кнопку *I'm Feeling Lucky*; текстовое поле тоже подошло бы) либо нажмите **Select on screen** и щёлкните якорь в приложении. Панель сообщает *target control was successfully identified*.
4. Если одного якоря мало, можно добавить несколько.

Сообщение на целевом контроле меняется на *selected item is unique*, и оранжевая полоса исчезает.

:::note
Названия режимов якоря взяты из речи; источник не объясняет, чем алгоритмы различаются. Не полагайтесь на точные названия опций, не проверив панель.
:::

## Identify by image

Tosca хранит битмап контрола и находит его на экране сопоставлением изображений. Это запасной вариант после anchor, и источник прямо говорит, что он должен быть последним средством перед index, потому что зависит от множества условий во время выполнения.

1. Выделите контрол и выберите **Identify by > Image**. Откроется панель **Identify by image**, где уже показано изображение контрола.
2. Нажмите кнопку **добавить изображение** (картинка с плюсом). Указатель станет крестом; обведите прямоугольником область для использования или нажмите **Return**, чтобы взять собственную область контрола. **Escape** отменяет; иконка-крестик отменяет, иконка сохранения сохраняет выделение.
3. Tosca предупреждает, что идентификация по изображению может привести к длительному периоду без видимого окна XScan. Ответьте **Yes** (отметьте *Remember my decision*, чтобы больше не спрашивало).
4. Заполните **image properties**: имя изображения — и проверьте значения, которые записала Tosca: **screen resolution** (разрешение экрана), **offset** (положение изображения относительно контрола), **method** (*full screen* в источнике) и **accuracy** (по умолчанию 95 %).

После этого контрол идентифицируется по свойствам **и** по изображению; XScan показывает оба. Слабые места — записанные значения: другое разрешение экрана при выполнении, изменившийся offset, метод, отличный от full screen, или совпадение ниже порога accuracy — всё это роняет шаг. Если используете метод, держите машины выполнения идентичными машине сканирования.

## Identify by index (ConstraintIndex)

Когда у нескольких контролов одинаковые свойства, индекс — это позиция цели среди них. Последний вариант в иерархии.

1. Выберите **Identify by > Index**. Панель **Identify by index** показывает предупреждение: используйте индекс, только если нельзя подобрать критерии, уникально идентифицирующие контрол.
2. Tosca уже определила, какой индекс у выбранного контрола; отметьте его. Сообщение меняется на *selected item is unique*.

Под капотом Module получает configuration parameter `ConstraintIndex` с этим числом; XScan сообщает, что контрол использует constraint index для идентификации. Индекс хрупок, потому что порядок одинаковых контролов может измениться вместе со страницей — на записанном индексе может оказаться похожий контрол. Тот же параметр можно создать вручную, см. [Свойства и параметры Module](/ToscaBase/ru/modules/module-properties-and-parameters/).

## ExplicitName: выбор из TestCase

Иногда фиксировать идентичность в Module вообще не хочется. В списке товаров у всех кнопок *Add to cart* одинаковые свойства; какую нажать, зависит от TestCase. С настройками по умолчанию имя TestStepValue в TestCase изменить нельзя, а клик по отсканированной кнопке падает после таймаута с ошибкой *more than one control found*.

1. В Module выделите атрибут и в панели **Properties** щёлкните правой кнопкой, выберите **Create configuration parameter**. Назовите его `ExplicitName`.
2. Установите `True`. (Допустим и диапазон значений; тогда TestCase может использовать любое имя из диапазона.)
3. В TestStep переименуйте атрибут в `#3`. Tosca нажмёт третью кнопку *Add to cart*.

Синтаксис `#n` — тот же индекс под другим именем, но он задаётся в каждом TestStep, а не зашивается в Module, поэтому один Module обслуживает любой товар. Источник называет его более стабильным, чем *Identify by index*; логика в том, что индекс выбирается там, где известен контекст. `ExplicitName` вместе с cardinality `0-n` — ещё и способ, которым один отсканированный элемент списка управляет многими пунктами, см. [Препятствия: идентификация контролов](/ToscaBase/ru/troubleshooting/obstacles-identification/).

## Сводка

| Метод | Когда | Риск |
|---|---|---|
| Properties | Всегда первым | Нет, если свойства стабильны |
| Anchor | Свойства не делают контрол уникальным, есть уникальный сосед | Сосед изменится |
| Image | Больше ничего не работает | Разрешение, offset, accuracy |
| Index | Больше ничего не работает, а image непрактичен | Порядок одинаковых контролов изменится |
| `ExplicitName` (`#n`) | Нужный контрол зависит от TestCase | Как у index, но выбирается на шаг |

Что бы вы ни выбрали, от этого зависит всё выполнение, поэтому выбирайте осознанно и фиксируйте выбор осмысленным именем атрибута.
