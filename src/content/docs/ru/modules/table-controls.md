Таблица, отсканированная в XScan, становится табличным контролом TBox: ModuleAttribute с фиксированной внутренней структурой из строк, столбцов и ячеек. В TestCase вы не адресуете ячейку через HTML; вы указываете строку, столбец и ячейку с помощью селекторов, Constraint (ограничений) и свойств, которые Tosca даёт для любой таблицы. Этот документ описывает структуру, селекторы, ActionMode, свойства и стандартные приёмы управления (steering). Проблемные таблицы (перемешанные строки, таблицы из `div`, неизвестное число строк) — в [Препятствиях: таблицы](/ToscaBase/ru/troubleshooting/obstacles-tables/); сравнение таблицы с сохранённым снимком — в [Сравнении таблицы с baseline](/ToscaBase/ru/modules/table-baseline-comparison/).

## Структура

Когда Module с таблицей перетаскивают в TestCase, TestStep показывает таблицу с двумя дочерними узлами — **Row** (строка) и **Column** (столбец), каждый с ячейками; значит, управлять нужно на трёх уровнях: строка (или столбец), ячейка в ней и значение или свойство ячейки. XScan показывает контрол с типом тега `table`.

Настройка **header row** (строка заголовка) в свойствах таблицы в Module по умолчанию указывает на первую строку; измените её, если заголовок в другом месте.

## Селекторы строк, столбцов и ячеек

Одни и те же селекторы работают для строк, столбцов и ячеек:

| Селектор | Смысл |
|---|---|
| `$1`, `$2`, `$3` ... | Строка, столбец или ячейка на фиксированной позиции |
| `$last` | Последняя строка, столбец или ячейка |
| `$header` | Ячейка в заголовке таблицы |
| `$lastContentRow` | Последняя строка, в которой есть значение |
| *first empty row* | Первая строка без значения |
| `#2` | Второе совпадение, когда Constraint подходит к нескольким строкам (см. пример 4) |

:::note
Автор произносит *last content row* и *first empty row* вслух, не показывая написания. `$lastContentRow` подтверждён уроком 125 ([Препятствия: таблицы](/ToscaBase/ru/troubleshooting/obstacles-tables/#последняя-строка-препятствие-19)); селектор первой пустой строки ищите в выпадающем списке значений узла строки.
:::

## ActionMode для таблиц

Обычные [ActionMode](/ToscaBase/ru/test-cases/action-modes/) действуют с табличной спецификой:

- **Input** — ввести значение в ячейку.
- **Verify** — проверить значение ячейки или свойство таблицы.
- **Constraint** — ограничить поиск. Constraint на ячейке выбирает строку (или столбец), где эта ячейка имеет заданное значение; остальная часть TestStep работает с этой строкой.
- **Buffer** — сохранить значение ячейки, строки или столбца в Buffer (буфер); см. [Buffer](/ToscaBase/ru/data-and-parameters/buffers/).

## Свойства таблицы

Задаются на узле таблицы (или строки/столбца/ячейки) выбором свойства вместо значения:

| Свойство | Возвращает |
|---|---|
| `ColumnCount` | Число столбцов |
| `RowCount` | Число строк |
| `ColumnNumber`, `RowNumber` | Индекс выбранного столбца или строки, считая с 0, относительно заголовочного столбца или строки |
| `RawColumnNumber`, `RawRowNumber` | Тот же индекс, считая с 1 |
| `ResultCount` | Число совпадений: ячеек с указанным содержимым либо, на узле строки без значения, число строк (включая заголовок) |

## Примеры steering

Все примеры используют таблицу списка препятствий Tricentis Obstacle Course (среди столбцов `ID`, `Name`, `Category`), отсканированную в Module `Obstacle list`; каждый пример — один его TestStep.

1. **Фиксированная позиция строки.** Строка `$3`, ячейка `Name`, ActionMode `Verify`, значение `Not a table`. Только когда номер строки никогда не меняется.
2. **Строка по значению ячейки (Constraint).** Строка, ячейка `Name` = `Fun with tables` с ActionMode `Constraint`; ячейка `Category` = `hard` с `Verify`. Tosca ищет значение Constraint во всех строках и выбирает подходящую. Два Constraint (например, `ID` и `Name`) сужают выбор, когда одно значение не уникально.
3. **Строка по значению без Constraint.** Значение ставится прямо на узел строки: строка = `Wait a moment`, затем ячейка `Category` = `easy` с `Verify`. Работает, только если значение уникально по всем строкам; на большой таблице это быстрее Constraint, которому приходится фильтровать строки.
4. **N-я подходящая строка.** Строка `#2`, ячейка `Category` = `easy` с `Constraint`, ячейка `Name` = `Twins` с `Verify`. Категория `easy` у нескольких строк; `#2` берёт вторую из них.
5. **Число строк и столбцов.** На узле таблицы выберите свойство `RowCount`, ActionMode `Verify`, значение `12`. То же с `ColumnCount`; догадка автора `10` не проходит, потому что в таблице девять столбцов. Проверка идёт на уровне таблицы, поэтому в логе меньше деталей, чем у проверки ячейки.
6. **Буферизация ячейки.** Столбец `Name`, ячейка `$5`, свойство `Text`, ActionMode `Buffer`, значение `b_name`. Buffer получает `Fun with tables`, что потом видно в Buffer Viewer.

Схема всегда одна: найти строку или столбец по критерию поиска, потом действовать с ячейкой в ней.

## Проверка числа строк и столбцов через Buffer

Пример 5 проверяет число напрямую; второй источник делает это в два шага, что полезно, когда ожидаемое число вычисляется в другом месте:

1. Узел таблицы → свойство `RowCount`, ActionMode `Buffer`, значение `rowcount`.
2. TestStep `TBox Evaluation Tool` с выражением `{B[rowcount]}==5`.
3. То же для `ColumnCount` в `columncount`, сравнение с `4`.

Строка заголовка учитывается: четыре строки данных дают `RowCount = 5`. Синтаксис выражений: [TBox Evaluation Tool](/ToscaBase/ru/standard-modules/evaluation-tool/).

Урок 24 так же буферизует `ResultCount` с узла строки корзины демо-магазина, отбрасывает заголовок через `TBox Set Buffer` и `{MATH[{B[cart items]}-1]}`, а результатом задаёт Repetition папки по строке `{REPETITION}`; см. [Repetition](/ToscaBase/ru/test-cases/repetitions/).

## Встроенные контролы внутри таблицы

Кнопку, ссылку или чекбокс, которые есть в каждой строке (ссылка *Go for it* в списке препятствий, чекбокс *Remove* в корзине веб-магазина), XScan сканирует как контрол **рядом** с таблицей, а не внутри строки. У всех таких контролов одинаковые свойства (`name` = `removefromcart`, `tag` = `input` у каждого чекбокса), поэтому управление одним из них падает с ошибкой *more than one control found*. Решение — сделать контрол частью ячейки, адресуемой через строку.

**Способ 1: переставить отсканированный контрол.** Отсканируйте таблицу и одну ссылку (сообщение *not unique* на контроле игнорируйте; если неуникальна сама таблица, нажмите **Make unique**, а чтобы увидеть элементы `table` и `tr`, повысьте **Filtered items**). В Module перетащите атрибут ссылки в ячейку строки, которая её содержит, чтобы дерево читалось так: таблица → строка → ячейка → ссылка. Заново добавьте Module в TestCase: строка `$1`, ячейка `Action` с ActionMode `Select`, ссылка → click попадает по ссылке первой строки. Для чекбокса: строка `$1`, ячейка `Remove` → `Select`, чекбокс → `True`.

**Способ 2: создать встроенный контрол вручную.** Когда отсканирована только таблица:

1. В Module щёлкните ячейку под строкой правой кнопкой, откройте меню **...** и выберите **Create embedded link control** (предлагаются **Create embedded checkbox control** и другие типы). Назовите его, например `Go`.
2. Щёлкните новый контрол правой кнопкой, снова откройте **...** и **Create technical ID parameter**. Добавьте известные свойства: `tag` = `a` и, по желанию, `InnerText` = `Go for it`. Без технических свойств контрол работает, только пока в ячейке один контрол этого business type: в уроке 30 параметры `name` и `tag` чекбокса снова удаляются, и строка `$2` → `Remove` → `True` по-прежнему работает.
3. В TestCase: строка `$1`, ячейка `Action` → `Select`, `Go` → метод click вводится вручную (для пользовательского контрола выпадающий список его не предлагает).

Оба способа годятся для любого контейнера, не только для таблиц; тот же приём решает препятствие 5 в [Препятствиях: таблицы](/ToscaBase/ru/troubleshooting/obstacles-tables/).
