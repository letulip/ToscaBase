XScan (сканер) создаёт TBox Module (XModule). Вы указываете ему на запущенное приложение, выбираете контролы, которые понадобятся TestCase, проверяете, что каждый контрол идентифицирован уникально, и сохраняете. Результат — Module, чьи ModuleAttribute (атрибуты модуля) содержат технические свойства этих контролов. Tosca предоставляет движки для сканирования многих технологий; здесь разобран веб-сайт в Chrome — то, что показывают источники. Словарь — в [Обзоре Module](/ToscaBase/ru/modules/modules-overview/).

:::note
В Tosca два сканера. Классический *Tosca Scan* (доступен и как отдельный мастер) создаёт классические Module; *XScan* создаёт TBox Module. Этот документ, как и вся база знаний, — про XScan.
:::

## Перед сканированием

1. Откройте тестируемое приложение и выведите на экран нужную страницу. XScan показывает приложения, открытые на рабочем столе; закрытое приложение отсканировать нельзя.
2. В Commander откройте секцию **Modules**. Папки стандартных Module (TBox Automation Tools, TBox XEngines, Test data related Modules) уже там.
3. Создайте папку для собственных Module и дайте ей осмысленное имя. Сканирование в папку отделяет пользовательские Module от стандартных.

## Запуск сканирования

Либо щёлкните папку правой кнопкой и выберите **Scan**, либо выделите папку и нажмите иконку **Scan** на вкладке **Modules** ленты Commander. Оба пути открывают один список типов сканирования; для веб- или десктоп-приложения выберите **Application**.

Tosca откроет диалог **Select application**. Он появляется через несколько секунд, потому что Tosca перечисляет все активные приложения на рабочем столе. Выберите окно браузера с вашей страницей и нажмите **Scan**.

## Окно XScan

XScan открывается в режиме **Basic view**: представление страницы, похожее на снимок экрана, где один щелчок по контролу добавляет его в Module. Переключитесь в **Advanced view**, чтобы увидеть дерево контролов с техническими свойствами каждого в виде флажков (у ссылки отмечены `InnerText` и `tag`; отметьте `class` или другое свойство, чтобы добавить его); методы идентификации, кроме свойств, доступны только там. Настройка **Filtered items** определяет, какая часть дерева показана; повысьте её, если контрол или его контейнер (`div`, `ul`) скрыт фильтром по умолчанию.

Выбор контролов:

- В Basic view — щёлкните контрол.
- В Advanced view — отметьте контролы в дереве либо включите **Select on screen** и щёлкайте их в приложении. Кнопка — переключатель, по умолчанию выключенный; нажмите её ещё раз, чтобы выйти из режима. В источниках так выбирают поисковую строку, логотип и кнопку.
- **Condensed view** прижимает панель XScan к правому краю экрана, так что всё приложение остаётся видимым; выбор работает так же.

Контролы, добавленные в одном режиме, сохраняются при переключении в другой. **Highlight selection** (Advanced view) обводит выбранный контрол в приложении — удобно на странице с множеством контролов; повторное нажатие снимает обводку. Каждый выбранный контрол добавляется в Module с предложенным именем и набором отмеченных технических свойств.

### Unique или not unique

После каждого выбора XScan проверяет, находят ли отмеченные свойства ровно один контрол на странице:

- **Selected item is unique** — делать ничего не нужно.
- **Selected item is not unique**, с оранжевой полосой на контроле — те же свойства подходят нескольким элементам. В источнике текстовое поле уникально, а кнопка поиска и логотип — нет.

Сообщение выводится внизу окна XScan, так что сразу видно, какие контролы ещё требуют внимания. Module можно сохранить и с неуникальными контролами, но TestStep на таком контроле упадёт при выполнении с ошибкой *more than one control found*.

Исправление неуникального контрола — отдельная тема: отметить больше технических свойств (логотип становится уникальным по свойству `alt`) или переключиться на идентификацию по anchor, image или index. Методы и порядок, в котором их пробовать, — в [Идентификации контролов](/ToscaBase/ru/modules/control-identification/).

## Переименовать, сохранить, сдать

1. Переименуйте каждый контрол в логическое имя (`Search box`, `Search button`) вместо технического по умолчанию. Имена переходят в TestStep и делают TestCase читаемым; см. [Соглашения об именовании](/ToscaBase/ru/best-practices/naming-conventions/).
2. Проверьте имя Module вверху окна XScan: предложенное имя берётся из заголовка страницы (`Demo Web Shop. Login`), и его можно отредактировать там же. Нажмите **Save** и закройте XScan. Новый Module появится в папке, в которую вы сканировали.
3. Выделите Module: его контролы перечислены в средней панели, а панель **Properties** справа показывает технические свойства каждого контрола в виде параметров (см. [Свойства и параметры Module](/ToscaBase/ru/modules/module-properties-and-parameters/)).
4. В многопользовательском workspace нажмите **Check in all**, чтобы Module попал в центральный репозиторий.

Теперь Module можно перетащить в TestCase, где каждый контрол станет TestStepValue; см. [Основы TestCase](/ToscaBase/ru/test-cases/test-case-basics/).

### Save или Finish screen

**Save** записывает Module и оставляет XScan открытым с выбранными контролами. Добавьте забытый контрол и нажмите **Save** ещё раз — обновится тот же Module, второй не создаётся. **Finish screen** тоже сохраняет, но очищает выбор, чтобы следующую страницу можно было отсканировать в новый Module, не закрывая XScan. При закрытии XScan с несохранёнными контролами Tosca спросит, сохранять ли; ответьте **No**, чтобы отбросить скан.

## Сканируйте только нужное

Выбирайте контролы, которые нужны TestCase, а не всю страницу, и разбивайте страницу на Module по функциональности. Страница, отсканированная целиком, медленнее управляется и раздувает workspace. Если позднему TestCase понадобится пропущенный контрол, добавьте его в существующий Module через [Пересканирование](/ToscaBase/ru/modules/rescan-modules/), а не сканируйте вторую копию. Обоснование — в [Гигиене Module](/ToscaBase/ru/best-practices/module-hygiene/).
