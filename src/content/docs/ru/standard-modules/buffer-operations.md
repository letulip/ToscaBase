Buffer (буфер) — именованное значение, живущее на время выполнения. Помимо ActionMode (режима действия) `Buffer` на любом контроле, модули TBox Automation Modules дают четыре отдельные операции с буферами. Поиск `TBox buffer` в **Add TestStep** показывает их все: **TBox Set Buffer**, **TBox Partial Buffer**, **TBox Name to Buffer** и **TBox Delete Buffer**. О самих буферах и Buffer Viewer см. [Буферы](/ToscaBase/ru/data-and-parameters/buffers/).

## TBox Set Buffer

Создаёт буфер или перезаписывает существующий заданным значением.

| ModuleAttribute | Значение |
|---|---|
| Buffer name | Имя создаваемого буфера, например `OrderNum` |
| Value | Значение: литерал, другой буфер `{B[...]}` или выражение |

Если переключить ActionMode значения на `Verify`, тот же модуль **проверяет** текущее значение существующего буфера вместо установки. Значение может быть выражением, поэтому шаг Set Buffer — обычное место для очистки значения, например обрезки пробелов в забуферизованном тексте.

## TBox Partial Buffer

Извлекает часть текста и сохраняет её в буфер.

| ModuleAttribute | Значение |
|---|---|
| Buffer name | Новый буфер для извлечённой части |
| Value | Исходный текст, обычно буфер вида `{B[OrderNum]}` |
| Start | Индекс первого символа |
| End | Индекс последнего символа |
| Last | Сколько символов взять, считая с конца текста |

- `Start` + `End` задают диапазон: `Start` = 1 и `End` = 5 возвращают первые пять символов.
- `Last` = 7 возвращает последние семь символов.
- **Не** сочетайте `Start`/`End` с `Last`: они противоречат друг другу. Выбирайте параметр под задачу.

С ActionMode `Verify` Partial Buffer сверяет извлечённую часть с ожидаемым значением вместо сохранения. Это имеет смысл только когда ожидаемое значение известно (например, из требований), а не для значений, которые приложение генерирует динамически.

## TBox Name to Buffer

Сохраняет в буфер **имя TestCase**, в котором находится шаг. Единственный атрибут — имя буфера (например `TC_Name`). Операция нишевая, но полезна, когда шагу нужно знать, в каком TestCase он выполняется.

:::caution
Name to Buffer работает только при запуске TestCase из **ExecutionList (списка выполнения)**. ScratchBook эту операцию не поддерживает.
:::

## TBox Delete Buffer

Удаляет один или несколько буферов по имени. Используйте как завершающий шаг очистки, перечислив все буферы, созданные в TestCase; лог подтверждает удаление каждого. Шаг необязателен: новое выполнение просто перезапишет буферы с теми же именами.

## Пример: извлечь номер заказа

Задача: из текста подтверждения вида `Your order number is: 1234567` (с пробелами вокруг) получить только число. Ранее использовалось длинное выражение из строковых операций (trim, replace с ignore-case); см. [Строковые операции](/ToscaBase/ru/expressions/string-operations/). Модули буферов дают более короткий вариант:

1. **Забуферизовать текст.** На контроле с текстом задать ActionMode `Buffer` и сохранить его inner text в `B_order`.
2. **TBox Set Buffer.** Имя буфера `OrderNum`, значение = функция trim, применённая к `{B[B_order]}`. Обрезка обязательна: иначе пробелы останутся при извлечении части.
3. **TBox Partial Buffer.** Имя буфера `OrderNumber`, значение `{B[OrderNum]}`, `Last` = 7. Считать с конца правильно, потому что текст перед числом имеет переменную длину, и для `Start`/`End` пришлось бы считать десятки символов.
4. **TBox Partial Buffer (Verify).** Тот же буфер, ActionMode `Verify`, ожидаемое = число; только для демонстрации, так как реальный номер заказа заранее неизвестен.
5. **TBox Name to Buffer.** Имя буфера `TC_Name`.
6. **TBox Delete Buffer.** `OrderNum`, `OrderNumber`, `TC_Name`.

Запускать из ExecutionList (это нужно шагу 5). В логе видно: `B_order` получает сырой текст с пробелами, затем обрезанное значение, затем семь извлечённых символов, успешную верификацию, имя TestCase в `TC_Name` и удаление трёх буферов.
