Операции с процессами в TBox Automation Modules позволяют TestCase запустить любой исполняемый файл, настольное приложение или браузер, а через команду Windows `taskkill` — закрыть работающие программы. Два сопутствующих модуля, TBox Start Timer и TBox Stop Timer, измеряют, сколько времени занимают шаги между ними, превращая функциональный шаг в простую проверку производительности.

## TBox Start Program

Добавьте модуль через **Add TestStep**, найдя `TBox Start Program`.

| ModuleAttribute | Значение |
|---|---|
| Path | Полный путь к исполняемому файлу, например `C:\Windows\notepad.exe` |
| Arguments | Аргументы командной строки |
| Wait for exit | Ждать ли завершения программы |
| Run as | Имя пользователя и пароль, если приложение должно работать под определённой учётной записью |

Для Notepad достаточно пути. Запуск шага в ScratchBook даёт Passed, и Notepad открывается в фоне.

### Запуск браузера с аргументами

Исполняемый файл Chrome лежит в `C:\Program Files\Google\Chrome\Application\chrome.exe` на 64-битных системах или в `Program Files (x86)` иначе. Укажите его в **Path** и добавьте два аргумента: ключ инкогнито и URL для открытия. Шаг запускает Chrome в режиме инкогнито сразу на нужной странице.

:::note
Точное написание аргумента инкогнито в видео не произносится; документированный ключ Chrome — `--incognito`.
:::

## Закрытие программ через taskkill

TBox Start Program не только запускает программы. Направьте его на команду Windows `taskkill`, и он завершит процессы: браузеры, редакторы, даже сам Tosca Commander. Типичный случай: тест настольного приложения должен начинаться с чистого рабочего стола и сначала закрывает всё остальное, чтобы никакая программа не мешала.

1. Добавьте **TBox Start Program**.
2. **Path**: `taskkill` (путь к исполняемому файлу не нужен).
3. **Arguments**: `/F /IM <имя образа>`.
   - `/IM` выбирает процесс по имени образа. Альтернатива — `/PID` (идентификатор процесса).
   - `/F` принудительно завершает все процессы с таким именем. Без него редактор может вместо закрытия показать окно «сохранить?», поэтому всегда добавляйте этот ключ.
4. Запустите шаг. В логе видно, что taskkill запущен с аргументами, а программа исчезает.

Имя образа находится в **Task Manager > Processes**: выбрать приложение, **Go to details**, прочитать столбец **Name**; там же показан PID. Примеры из видео:

| Программа | Имя образа |
|---|---|
| Google Chrome (все вкладки и окна) | `chrome.exe` |
| Notepad++ | `notepad++.exe` |
| Tosca Commander | `ToscaCommander.exe` |

:::caution
Завершение `ToscaCommander.exe` закрывает Commander, в котором вы работаете; сначала всё сохраните. В интерактивной работе это редко нужно, но полезно, когда пакетный файл открывает Commander и прогоняет тесты через TCShell, а потом Commander надо закрыть. См. [Инструменты командной строки](/ToscaBase/ru/administration/command-line-tools/).
:::

## Измерение длительности: TBox Start Timer и TBox Stop Timer

1. TestCase **Start timer**: добавьте **TBox Start Timer** с **ID**, например `Timer1`.
2. TestCase (один или несколько), которые нужно измерить, например запускающий Chrome.
3. TestCase **Stop timer**: добавьте **TBox Stop Timer** с тем же **ID**.

Запустите папку. В результатах запись Start Timer показывает старт таймера, а запись Stop Timer содержит **Measured value**: время, которое заняли шаги между таймерами (в примере 28 мс на открытие браузера).

### Таймер как проверка производительности

У TBox Stop Timer есть также **Maximum duration**. Заполните его и задайте ActionMode `Verify`: если измеренное время превысит максимум, шаг Stop Timer упадёт с сообщением ожидаемое/фактическое, и TestCase будет помечен как не отвечающий требованиям производительности.

:::note
В видео максимум задан как 10, а сообщение об ошибке описано как «ожидалось меньше 10, заняло 43», причём единицы названы то миллисекундами, то секундами. Проверьте, в каких единицах Tosca показывает Measured value в вашей версии, прежде чем выбирать лимит.
:::

## Очистка кэша Chrome

Остатки данных браузера могут повлиять на выполнение, поэтому очистка кэша — частый подготовительный шаг перед веб-тестами. Вручную это делается в Chrome через **Settings > More tools > Clear browsing data** (отметить кэшированные изображения и файлы, при желании историю, дополнительно в Advanced, затем Clear data). Для автоматизации TBox Start Program запускает командную строку Windows с командой удаления.

1. Добавьте **TBox Start Program** в TestCase (например `Chrome cache`).
2. **Path**: `cmd`.
3. **Arguments** в таком порядке: `/C`, затем `del`, затем `/Q /S /F`, затем путь к папке кэша в двойных кавычках.

| Аргумент | Значение |
|---|---|
| `/C` | Указывает cmd выполнить следующую за ним команду |
| `del` | Команда удаления Windows |
| `/F` | Принудительно удалять файлы только для чтения без запроса подтверждения (запрос — это `/P`, в автоматизации его надо избегать) |
| `/S` | Удалить указанные файлы из заданной папки и показать имена удаляемых файлов |
| `/Q` | Тихий режим, работа в фоне |
| `"<путь>"` | Папка кэша Chrome; кавычки не дают обратным слешам и пробелам в пути исказить значение |

При установке Chrome в место по умолчанию кэш находится в `C:\Users\<user>\AppData\Local\Google\Chrome\User Data\Default\Cache`; при нестандартной установке путь другой. Полный синтаксис команды удаления можно найти по запросу *Windows cmd del*.

Запустите шаг в ScratchBook: на мгновение появляется чёрное окно консоли, перечисляет удаляемые файлы и закрывается; шаг проходит, папка кэша после этого пуста. Тот же TestStep очищает кэш Internet Explorer или Firefox, если аргумент пути указывает на их папку кэша.
