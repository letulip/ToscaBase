ExecutionList может содержать ручные TestCase, а любой автоматизированный TestCase можно запустить **как ручной тест**: Tosca ведёт вас по TestStep в чек-листе, вы проверяете каждый шаг в приложении и фиксируете pass или fail, а результат попадает в `ActualLog` как обычный автоматический прогон. Отдельно можно перезаписать результат execution entry, ничего не выполняя. И то и другое помогает держать ExecutionList правдивым, когда автоматизация не успевает.

## Когда запускать автоматизацию вручную

Типичный случай: автоматизированный TestCase падает на каком-то шаге, времени чинить оставшиеся шаги нет, а решение о релизе нужно сегодня. Запустите ту же запись как ручной тест, проверьте приложение руками по TestStep, и заинтересованные стороны получат полный результат с доказательствами.

## Run as manual TestCase

1. В ExecutionList правый клик по execution entry, папке записей или всему списку > **Run as manual TestCase** (`Ctrl+Shift+M`).
2. Откроется **окно чек-листа**. В нём перечислены все TestStep со значениями, ActionMode и предыдущими результатами.
3. Для каждого шага выполните его в приложении и нажмите **Pass** или **Fail** в колонке результата. Счётчик папки обновляется (например, 1 из 64 шагов прошёл). Результат можно снова очистить.
4. При желании добавьте к шагу **комментарий**, **вложение** или **скриншот**. Инструмент скриншота умеет аннотации (стрелки, линии, текстовые поля) и **Save and close**.
5. По окончании нажмите **Finish**.

Под записью появится новый лог выполнения с прошедшими и упавшими шагами, а также прикреплёнными скриншотами и комментариями. Поскольку чек-лист несёт значения, скриншоты и комментарии, результат заодно служит живым тестовым документом.

### Элементы окна чек-листа

- **Collapse / Expand**: свернуть окно, чтобы приложение оставалось видно, и развернуть обратно.
- **Mini size / Full size**: показать только текущий выполняемый шаг или весь чек-лист.
- **Enable automation / Manual**: когда ручная часть закончена, пометить оставшиеся шаги как автоматизированные и продолжить прогон автоматически; обратный переключатель тоже есть.
- **Inject data value**: отправить значение выбранного TestStep в тестируемую систему.
- **Set passed / Set failed** на верхней панели, эквивалент кнопок в колонке результата.
- **Pause**: активна во время автоматического прогона, ставит его на паузу.

## Установка результата вручную

Чтобы изменить зафиксированный результат execution entry без запуска:

1. Правый клик по execution entry > **Set result**.
2. Выберите **Passed**, **Failed** или **No result**.
3. Введите комментарий по запросу (например `manually set to no result`) и подтвердите.

Последнее выполнение покажет новый результат, log info запишет, **кто** его установил, и комментарий, а время начала попадёт в лог. Вручную выставленный сбой также помечает содержащий TestCase как упавший в статистике.

Используйте это, чтобы сбросить запись в **No result** в начале релизного цикла или зафиксировать сбой, найденный руками в функции, до которой автоматизация не дошла.
