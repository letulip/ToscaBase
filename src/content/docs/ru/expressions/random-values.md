TestStepValue (значение тестового шага) не обязано быть фиксированной строкой. В Tosca есть набор динамических выражений в фигурных скобках, которые при каждом прогоне генерируют новое случайное целое число, дробь или строку. Благодаря этому один TestCase (тестовый случай) годится для форм регистрации, уникальных идентификаторов и любых полей, отвергающих повторяющиеся данные. Вторая половина страницы посвящена обратной задаче: случайное значение создаёт само *приложение*, а тест должен его прочитать, посчитать с ним или выбрать его в списке.

## Выражения-генераторы

Каждое выражение вводится в столбец **Value** тестового шага. Как только вы набираете `{`, Tosca открывает список автодополнения с доступными выражениями; выберите нужное или введите имя, затем добавьте аргументы в квадратных скобках и закройте фигурную скобку. После нажатия Enter корректное выражение подсвечивается в ячейке.

| Выражение | Что генерирует | Пример |
|---|---|---|
| `{RND[длина]}` | Целое число заданного количества цифр, без ограничений диапазона. Длина любая (в видео названы 9, 10, 50, 100). | `{RND[10]}` для 10-значного телефона |
| `{RND[нижняя][верхняя]}` | Целое число между нижней и верхней границей. | `{RND[1000][10000]}` |
| `{RNDDECIMAL[длина][знаков после запятой]}` | Число заданной длины с заданным числом десятичных знаков (2, 3, 4...). | `{RNDDECIMAL[5][2]}` |
| `{RNDDECIMAL[знаков после запятой][нижняя][верхняя]}` | Дробное число с заданным числом десятичных знаков в диапазоне. | `{RNDDECIMAL[2][1000][10000]}` |
| `{RANDOMTEXT[длина]}` | Случайная строка заданной длины из букв и цифр. | `{RANDOMTEXT[5]}` |

Автор упоминает, что можно сгенерировать и строку с меткой времени, но не показывает это; см. `DATETIME` в разделе [Выражения дат](/ToscaBase/ru/expressions/date-expressions/).

:::note
Транскрипты сделаны по субтитрам, поэтому порядок аргументов `RNDDECIMAL` взят так, как автор его проговаривает (сначала длина, потом число знаков; либо число знаков, потом диапазон). Написание имён выражений соответствует именам из списка автодополнения Tosca. Если после Enter значение не подсвечено, выражение составлено неверно. Проверяйте результат через **Translate value** (ниже).
:::

## Проверка результата выражения

Щёлкните правой кнопкой по TestStepValue и выберите **Translate value**. Tosca покажет конкретное значение, которое сгенерирует: пять символов из букв и цифр для `{RANDOMTEXT[5]}`, десятизначное число для `{RND[10]}`. Это самый быстрый способ проверить выражение до запуска.

## Пример: регистрация аккаунта

Тест заполняет форму регистрации (имя, фамилия, e-mail, телефон, пароль, подтверждение пароля, переключатель рассылки, чекбокс политики конфиденциальности и кнопка **Continue**).

1. Создайте папку TestCase для приложения и два тестовых случая: `Open application` (стандартный Module (модуль) `OpenUrl` с адресом, ActionMode **Input**, плюс Test Configuration Parameter (параметр тестовой конфигурации) `Browser` = `Chrome`) и `Register account`.
2. Отсканируйте страницу регистрации в новый Module и перетащите его на `Register account`. Нажмите **Ctrl+T** на тестовом случае, чтобы искать по всем модулям рабочего пространства, не открывая раздел Modules.
3. Задайте значения:
   - Имя: `{RANDOMTEXT[5]}`
   - Фамилия: `{RANDOMTEXT[5]}`
   - E-mail и пароль: статические значения (в видео введены фиксированные)
   - Телефон: `{RND[10]}`
   - Переключатель: клик; чекбокс: `true`/`false`; кнопка Continue: клик
4. Запустите в ScratchBook. В логе при каждом прогоне видны новые имя и телефон.

Запуск в видео падает на переключателе с ошибкой *more than one control found*: два контрола имеют одинаковые свойства идентификации. Это проблема модуля, а не выражения; решается пересканированием модуля и выбором уникального свойства (см. [Пересканирование модулей](/ToscaBase/ru/modules/rescan-modules/) и [Идентификация контролов](/ToscaBase/ru/modules/control-identification/)).

:::tip
Случайный *пароль* нужно ввести дважды (пароль и подтверждение) с одним значением, поэтому `{RANDOMTEXT[8]}` в каждом поле не совпадёт. В видео этот случай отложен; приём такой: сгенерировать значение один раз, сохранить в [Buffer (буфер)](/ToscaBase/ru/data-and-parameters/buffers/) и использовать буфер в обоих полях.
:::

## Случайные значения, которые создаёт приложение

Три сценария из курса препятствий показывают, как использовать случайные данные, а не генерировать их. Все они опираются на ActionMode **Buffer** (см. [ActionModes](/ToscaBase/ru/test-cases/action-modes/)).

### Прочитать два случайных числа и сложить их (MATH, SENDKEYS)

Страница показывает два случайно сгенерированных числа и ждёт их сумму в текстовом поле.

1. Отсканируйте оба числовых элемента и поле результата; переименуйте ModuleAttribute (атрибуты модуля) в `num1`, `num2` и `result`.
2. Для `num1` и `num2` задайте ActionMode **Buffer**, буферизуйте свойство `InnerText` и дайте каждому буферу имя.
3. В `result` не пишите `{B[num1]}+{B[num2]}`: голый `+` между двумя буферами не даёт результата. Арифметика выполняется только через математическое выражение: `{MATH[{B[num1]}+{B[num2]}]}` (операнды — буферы, оператор `+`; вычитание, умножение и деление работают так же).
4. Сумма вводится верно, но препятствие не засчитывается: страница ждёт посимвольного ввода. Оберните то же выражение в **SendKeys**, чтобы Tosca эмулировала набор пользователем: `{SENDKEYS["{MATH[{B[num1]}+{B[num2]}]}"]}`. С SendKeys препятствие проходится.

Перед запуском из ScratchBook переводите workstate (состояние работы) тестового случая в **Completed**, как это каждый раз делает автор.

### Буферизовать случайный текст и выбрать его в комбобоксе

Кнопка генерирует случайную строку, которая одновременно есть среди пунктов выпадающего списка; тест должен выбрать совпадающий пункт и отправить форму.

| TestStep | ModuleAttribute | ActionMode / значение |
|---|---|---|
| Click random button | Кнопка Generate random text | клик (`X`) |
| Buffer random text | Текстовое поле | **Buffer**, значение `RND` (имя буфера) |
| Select random text | Выпадающий список | **Select**, значение `{B[RND]}` |
| Click submit | Кнопка Submit | клик (`X`) |

Модуль перетаскивается четыре раза, по одному TestStep (тестовому шагу) на действие, и каждый шаг переименовывается. Рекомендация автора: одно действие или одно значение на шаг.

### Извлечь несколько случайных чисел из случайной строки (именованные группы)

Клик по первому полю открывает случайное предложение с тремя большими числами, которые нужно ввести в три других поля. Буферизовать весь текст недостаточно; числа извлекаются регулярным выражением с **именованными группами**, каждая из которых сохраняет совпадение в буфер:

```
{REGEX[^.*(?<number1>[0-9]+).*(?<number2>[0-9]+).*(?<number3>[0-9]+).*$]}
```

Каждая группа `(?<имя>...)` сохраняет своё совпадение в буфер с этим именем; сам синтаксис именованных групп объяснён в разделе [Извлечение частей значения именованными группами](/ToscaBase/ru/expressions/intervals-and-verification-expressions/#извлечение-частей-значения-именованными-группами). Здесь группы разделены `.*`, поглощающим окружающий текст, а шаблон закреплён `^` и `$`. Как и там, у шага должен быть ActionMode **Verify** («input is not supported for regex values»).

Затем три поля заполняются значениями `{B[number1]}`, `{B[number2]}` и `{B[number3]}`.
