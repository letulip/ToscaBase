Точная строка не всегда подходит для идентификации контрола или проверки значения: скидка должна лишь попадать в диапазон, заголовок страницы меняется вместе с языком интерфейса, идентификатор транзакции предсказуем лишь частично. Tosca принимает два семейства выражений везде, где сравнивается значение: **интервалы**, проверяющие, что число лежит в диапазоне, и **регулярные выражения**, сопоставляющие шаблоны в свойствах идентификации ModuleAttribute (атрибута модуля) и в TestStepValue (значение шага теста) с ActionMode **Verify**. С *именованными группами* регулярное выражение ещё и разрезает совпавший текст на части и сохраняет каждую в Buffer (буфер).

## Интервалы: проверка значения в диапазоне

Интервалы работают только с ActionMode **Verify**, с числовым или строковым типом данных и с операторами сравнения `==` и `!=`. Вместо фиксированного ожидаемого значения TestStepValue задаёт базу и допустимое отклонение фактического значения от неё. Ввод `{INTERVAL` в ячейке значения показывает описание Tosca, синтаксис и пример.

| Тип | Синтаксис | Допустимый диапазон | Пример |
|---|---|---|---|
| Простой интервал (равные границы) | `{INTERVAL[база][предел]}` | от база − предел до база + предел | `{INTERVAL[10][5]}` проходит для любого значения от 5 до 15 |
| Пользовательский интервал (разные границы) | `{INTERVAL[база][нижняя граница][верхняя граница]}` | от база − нижняя граница до база + верхняя граница | `{INTERVAL[10][6][5]}` проходит для 4..15 |

Собственное описание Tosca использует базу 100: предел 25 даёт 75..125; нижняя граница 10 и верхняя 50 дают 90..150.

Пример (демо-приложение Tricentis Vehicle Insurance): после ввода данных об автомобиле, страховке и продукте экран *Select price option* показывает таблицу тарифов (silver, gold, platinum, ultimate) со строкой *claims discount*. Скидка зависит от введённых данных, но всегда остаётся между 0 и 10, поэтому статическая `5` сломала бы TestCase (тест-кейс).

1. Перетащите отсканированный табличный Module (модуль) `Select price option` в TestCase; столбец `Platinum`, строка адресуется полным текстом подписи вместо индекса ячейки.
2. Прогоните с ActionMode **Buffer** в `B_discount`, чтобы убедиться, что ячейка читается; в логе `5`.
3. Скопируйте шаг с ActionMode **Verify** и `{INTERVAL[10][5]}`, затем ещё один с `{INTERVAL[10][6][5]}` (4..15; в уроке 37 — `{INTERVAL[10][5][5]}`). Обе проверки проходят. Корректное выражение подсвечивается, как только вы уходите из ячейки; обычный текст означает пропущенную скобку.

:::note
Проверка интервалом не пишет строку в log info; подтверждением, что значение попало в диапазон, служит пройденный TestCase. В обоих уроках сказано, что интервалы применимы и к строкам, но показаны только числа.
:::

## Выражение REGEX

```
{REGEX["шаблон"]}
```

Наберите `{`, выберите `REGEX` в автодополнении и поместите шаблон в двойных кавычках внутрь квадратных скобок; в уроке 33 кавычки опущены (`{REGEX[шаблон]}`), и прогон тоже проходит. Собственное описание Tosca добавляет форму для извлечения текста:

```
{REGEX[выражение(?<ИмяБуфера>подвыражение)выражение]}
```

Выражение целиком проверяет, что текст соответствует шаблону; каждая именованная группа `(?<ИмяБуфера>подвыражение)` сохраняет своё совпадение в буфер с этим (произвольным) именем, а подвыражение описывает динамическую часть.

| Элемент regex | Значение (как используется в видео) |
|---|---|
| `^` ... `$` | Начало и конец текста |
| `.*`, `.*?` | Любые символы в любом количестве (жадно или лениво — как можно меньше) |
| `\|` | Альтернатива: левый или правый шаблон |
| `[0-9]+` | Одна или больше цифр |
| `[A-Z]*` | Любое число заглавных латинских букв |
| `\d{3}` | Ровно три цифры |
| `\d*` | Любое число цифр (остаток числа) |
| `(?<имя>...)` | Именованная группа; совпадение сохраняется в буфер `имя` |

## Многоязычная идентификация через альтернативы

Сайт на английском и французском сохраняет вёрстку, но заголовок страницы и тексты ссылок меняются с языком. Контрол с языконезависимым свойством, например ID, продолжает работать; ссылка *Cameras* из примера идентифицируется только по `InnerText` и тегу, поэтому переключение на французский ломает и заголовок страницы в Module, и ссылку. Вместо Module на каждый язык объедините оба текста в одно регулярное выражение через `|` в свойстве идентификации:

| Свойство ModuleAttribute | Значение |
|---|---|
| Заголовок страницы (Module) | `{REGEX["Cameras from Nikon.*\|Appareils photo.*"]}` |
| `InnerText` ссылки Cameras | `{REGEX["Cameras\|Appareils photo.*"]}` |

Каждая альтернатива оставляет только постоянную часть и заканчивается `.*`, чтобы хвост мог меняться; добавьте по альтернативе на язык для каждого переводимого контрола. TestCase `Click cameras` (один Module, клик по ссылке) проходит и на французской, и на английской версии.

То же работает для целого текстового блока (урок 33, moodle.org на английском и нидерландском): абзац описания, идентифицированный по полному `InnerText` и проверяемый через `Exists == true`, на нидерландском падает, пока `InnerText` не станет `{REGEX[английский абзац|нидерландский абзац]}` — нидерландский текст скопирован из панели inspect браузера; после этого TestCase проходит на обоих языках.

:::note
Французский текст ссылки в уроке 35 только показан на экране; `Appareils photo` — стандартный французский вариант *Cameras*. Сверяйте точные строки (в Chrome: inspect, поиск по `title` или по inner text элемента) на автоматизируемой странице.
:::

## Извлечение частей значения именованными группами

Идентификатор транзакции вида `IN` + аббревиатура банка + трёхзначное число + ещё цифры нужно разбить на четыре буфера для последующих проверок.

1. `TBox Set Buffer`: буфер `trans` = идентификатор транзакции.
2. Второй `TBox Set Buffer` с *тем же* именем буфера `trans`, регулярным выражением в качестве значения и ActionMode **Verify**:

   ```
   {REGEX[(?<part1>IN)(?<part2>[A-Z]*)(?<part3>\d{3})(?<part4>\d*)]}
   ```

| Группа | Подвыражение | Что попадает в буфер |
|---|---|---|
| `part1` | `IN` | Статический префикс |
| `part2` | `[A-Z]*` | Буквы до первой цифры, сколько бы их ни было |
| `part3` | `\d{3}` | Ровно следующие три цифры |
| `part4` | `\d*` | Все оставшиеся цифры |

3. Переведите workstate (состояние работы) в Completed и запустите; с ActionMode **Input** прогон падает (*input is not supported for regex values*), извлечение через `REGEX` требует **Verify**.
4. Откройте **Tools > Buffer Viewer**; поиск по `part` показывает четыре буфера.

Тот же приём читает три случайных числа из случайного предложения в разделе [Случайные значения](/ToscaBase/ru/expressions/random-values/), где группы разделены ленивыми `.*?`, а шаблон закреплён `^` и `$`.

## Что когда использовать

| Ситуация | Подход |
|---|---|
| Число может меняться, но должно оставаться в диапазоне | `{INTERVAL[база][предел]}` или `{INTERVAL[база][нижняя][верхняя]}`, ActionMode Verify |
| Текст контрола зависит от языка или имеет переменный хвост | `{REGEX["..."]}` с `\|` и `.*` в свойстве идентификации |
| Проверить, что значение соответствует шаблону | `{REGEX["..."]}` как TestStepValue, ActionMode Verify |
| Проверить и разбить значение на буферы | Именованные группы внутри `REGEX`, ActionMode Verify |
| Убрать префикс или спецсимвол из буферизованного значения; совпасть с любым хвостом через голый `*` | [Строковые операции](/ToscaBase/ru/expressions/string-operations/) |

Об ActionMode см. [ActionModes](/ToscaBase/ru/test-cases/action-modes/); о буферах — [Буферы](/ToscaBase/ru/data-and-parameters/buffers/); об адресации ячеек таблицы по столбцу и строке — [Табличные контролы](/ToscaBase/ru/modules/table-controls/).
