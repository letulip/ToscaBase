Точная строка не всегда подходит для идентификации контрола или проверки значения. Скидка зависит от введённых данных и должна лишь попадать в диапазон; заголовок страницы меняется вместе с языком интерфейса; идентификатор транзакции предсказуем лишь частично. Tosca принимает два семейства выражений везде, где сравнивается значение: **интервалы**, проверяющие, что число лежит в диапазоне, и **регулярные выражения**, сопоставляющие шаблоны в свойствах идентификации ModuleAttribute (атрибута модуля) и в TestStepValue (значение шага теста) с ActionMode **Verify**. С *именованными группами* регулярное выражение ещё и разрезает совпавший текст на части и сохраняет каждую в Buffer (буфер).

## Интервалы: проверка значения в диапазоне

Интервалы работают только с ActionMode **Verify**, с числовым или строковым типом данных и с операторами сравнения `==` и `!=`. Вместо фиксированного ожидаемого значения TestStepValue задаёт базу и допустимое отклонение фактического значения от неё. Ввод `{INTERVAL` в ячейке значения показывает описание Tosca, синтаксис и пример.

| Тип | Синтаксис | Допустимый диапазон | Пример |
|---|---|---|---|
| Простой интервал (равные границы) | `{INTERVAL[база][предел]}` | от база − предел до база + предел | `{INTERVAL[10][5]}` проходит для любого значения от 5 до 15 |
| Пользовательский интервал (разные границы) | `{INTERVAL[база][нижняя граница][верхняя граница]}` | от база − нижняя граница до база + верхняя граница | `{INTERVAL[10][5][5]}` проходит для 5..15; измените любую границу, чтобы сдвинуть диапазон |

Пример из приложения Tricentis Vehicle Insurance: после ввода данных об автомобиле, страховке и продукте экран *Select price option* показывает таблицу тарифов (gold, platinum...) со строкой *claims discount*. Скидка меняется в зависимости от введённых данных, но всегда остаётся между 2 и 10, поэтому проверка статической `5` сломала бы TestCase (тест-кейс).

1. Перетащите отсканированный табличный Module (модуль) `Select price option` в TestCase.
2. В столбце выберите `Platinum`; ячейку строки идентифицируйте, набрав полный текст подписи строки вместо индекса ячейки, чтобы шаг адресовал ячейку claims discount.
3. Сначала прогоните с ActionMode **Buffer** в `B_discount`, чтобы убедиться, что ячейка читается верно; лог показывает в буфере `5`.
4. Скопируйте шаг, задайте ActionMode **Verify** и значение `{INTERVAL[10][5]}` (простой интервал), затем ещё одну копию с `{INTERVAL[10][5][5]}` (пользовательский интервал). Обе проверки проходят.

:::note
Проверка интервалом не пишет строку в log info; подтверждением, что значение попало в диапазон, служит пройденный TestCase. Автор утверждает, что интервалы применимы и к строкам, но показывает только числа; расчёт диапазона демонстрируется только для числовых значений.
:::

## Выражение REGEX

```
{REGEX["шаблон"]}
```

Наберите `{`, выберите `REGEX` в автодополнении, откройте квадратную скобку, поместите шаблон в двойные кавычки, закройте скобку и фигурную скобку. Собственное описание выражения в Tosca добавляет форму для извлечения текста:

```
{REGEX[выражение(?<ИмяБуфера>подвыражение)выражение]}
```

Выражение целиком проверяет, что текст соответствует шаблону; каждая группа `(?<ИмяБуфера>подвыражение)` — именованная, и её совпадение сохраняется в буфер с этим именем. Имя буфера произвольное; подвыражение описывает динамическую часть.

| Элемент regex | Значение (как используется в видео) |
|---|---|
| `^` ... `$` | Начало и конец текста |
| `.*` | Любые символы в любом количестве |
| `*` после литерала | Литерал и что угодно после него (`Cameras from Nikon.*`) |
| `\|` | Альтернатива: левый или правый шаблон |
| `[0-9]+` | Одна или больше цифр |
| `[A-Z]*` | Любое число заглавных латинских букв |
| `\d{3}` | Ровно три цифры |
| `\d*` | Любое число цифр (остаток числа) |
| `(?<имя>...)` | Именованная группа; совпадение сохраняется в буфер `имя` |

## Многоязычная идентификация через альтернативы

Сайт на английском и французском сохраняет вёрстку, но заголовок страницы и тексты ссылок меняются с языком. Если у контрола есть языконезависимое свойство, например ID, идентификация продолжает работать; у ссылки *Cameras* из примера его нет, она идентифицируется только по `InnerText` и тегу, поэтому переключение сайта на французский ломает и заголовок страницы в Module, и ссылку.

Создавать по Module на каждый язык неэффективно. Вместо этого объедините оба текста в одно регулярное выражение через `|` и используйте его в свойстве идентификации:

| Свойство ModuleAttribute | Значение |
|---|---|
| Заголовок страницы (Module) | `{REGEX["Cameras from Nikon.*\|Appareils photo.*"]}` |
| `InnerText` ссылки Cameras | `{REGEX["Cameras\|Appareils photo.*"]}` |

Каждая альтернатива оставляет только постоянную часть текста и заканчивается `.*`, чтобы хвост мог меняться. Тот же приём масштабируется на любое число языков: добавьте по альтернативе на язык для каждого контрола с переводимым текстом. TestCase `Click cameras` — один Module, клик по ссылке — проходит и на французской, и на английской версии сайта.

:::tip
Чтобы увидеть текущий заголовок страницы в Chrome, откройте инструменты разработчика (inspect) и найдите `title`.
:::

:::note
Автор читает французский текст ссылки вслух (звучит как «April photo»), но не проговаривает по буквам, а французский заголовок только показан на экране. `Appareils photo` — стандартный французский вариант *Cameras*; сверяйте точные строки на автоматизируемой странице.
:::

## Извлечение частей значения именованными группами

Идентификатор транзакции вида `IN` + аббревиатура банка + трёхзначное число + ещё цифры нужно разбить на четыре буфера для последующих проверок.

1. `TBox Set Buffer`: буфер `trans` = идентификатор транзакции.
2. Второй `TBox Set Buffer` с *тем же* именем буфера `trans`, регулярным выражением в качестве значения и ActionMode **Verify**:

   ```
   {REGEX[(?<part1>IN)(?<part2>[A-Z]*)(?<part3>\d{3})(?<part4>\d*)]}
   ```

| Группа | Подвыражение | Что попадает в буфер |
|---|---|---|
| `part1` | `IN` | Статический префикс |
| `part2` | `[A-Z]*` | Буквы до первой цифры, сколько бы их ни было |
| `part3` | `\d{3}` | Ровно следующие три цифры |
| `part4` | `\d*` | Все оставшиеся цифры |

3. Переведите workstate (состояние работы) TestCase в Completed и запустите. С ActionMode **Input** прогон падает с сообщением, что значение должно быть входным; извлечение текста через `REGEX` требует **Verify**.
4. Проверьте результат в **Tools > Buffer Viewer**; поиск по `part` показывает четыре буфера со значениями.

Тот же приём читает три случайных числа из случайного предложения в разделе [Случайные значения](/ToscaBase/ru/expressions/random-values/), где группы разделены `.*`, а шаблон закреплён `^` и `$`.

## Что когда использовать

| Ситуация | Подход |
|---|---|
| Число может меняться, но должно оставаться в диапазоне | `{INTERVAL[база][предел]}` или `{INTERVAL[база][нижняя][верхняя]}`, ActionMode Verify |
| Текст контрола зависит от языка или имеет переменный хвост | `{REGEX["..."]}` с `\|` и `.*` в свойстве идентификации |
| Проверить, что значение соответствует шаблону | `{REGEX["..."]}` как TestStepValue, ActionMode Verify |
| Проверить и разбить значение на буферы | Именованные группы внутри `REGEX`, ActionMode Verify |
| Убрать фиксированный префикс или спецсимвол из буферизованного значения | [Строковые операции](/ToscaBase/ru/expressions/string-operations/) (`STRINGREPLACE`, `TRIM`) |
| Совпадение с любым хвостом в свойстве Module без полного regex | Подстановочный символ `*`, как в `Order number*` (см. Строковые операции) |

Об ActionMode см. [ActionModes](/ToscaBase/ru/test-cases/action-modes/); о буферах — [Буферы](/ToscaBase/ru/data-and-parameters/buffers/); об адресации ячеек таблицы по столбцу и строке — [Табличные контролы](/ToscaBase/ru/modules/table-controls/).
