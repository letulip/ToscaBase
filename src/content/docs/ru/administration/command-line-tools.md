Два исполняемых файла в папке установки Tosca Commander выполняют административную работу без интерфейса Commander. **TCShell** открывает workspace из командной строки и выполняет команды над ним: запустить ExecutionList, сохранить результаты, сделать check-in (вернуть объекты в репозиторий). На нём строится любая интеграция с CI (см. [Интеграция с CI через Jenkins](/ToscaBase/ru/execution/ci-integration-jenkins/)). **TCWorkspaceUtil** клонирует workspace, чтобы каждый участник команды получил рабочую копию, подключённую к общему репозиторию.

Оба лежат в каталоге установки Commander, по умолчанию `C:\Program Files\Tricentis\Tosca Commander`. Переменная окружения `%COMMANDER_HOME%` указывает туда; введите её в адресную строку Проводника, и папка откроется.

## TCShell

TCShell устанавливается вместе с Commander; ничего настраивать не нужно. Он принимает workspace, который нужно открыть, и, для многопользовательского workspace, учётные данные:

| Параметр | Значение |
|---|---|
| workspace | Полный путь к файлу workspace, вплоть до файла `.tws` |
| login | Имя пользователя и пароль. Не нужны для однопользовательского workspace; обязательны в многопользовательском |
| script | Путь к файлу скрипта `.tcs` (только скриптовый режим) |

:::note
Точное написание ключей показано только на экране и не проговаривается. Выполните `help` внутри TCShell (или обратитесь к документации Commander), чтобы узнать точный синтаксис, прежде чем писать batch-файл.
:::

### Интерактивный режим

Запустите TCShell с параметром workspace. Он проверяет лицензию и входит в workspace; появление приглашения означает, что вы подключены. Введите `help`, чтобы увидеть список команд. Те, что выделяет источник:

| Команда | Назначение |
|---|---|
| compact workspace | Сжимает workspace ради производительности |
| change node, jump to node | Переход к объекту по его пути в дереве проекта |
| call script | Выполнить скрипт `.tcs` |
| get option, set option, save options | Чтение и изменение параметров |
| set property | Изменить свойство текущего объекта |
| health check | Фоновая проверка workspace |
| task | Выполнить задачу над текущим объектом, например запустить ExecutionList; также check in all |

Интерактивный режим задаёт вопросы, где нужно: как выйти, продолжать ли при заблокированном workspace. По окончании выйдите командой выхода.

:::caution
Однопользовательский workspace нельзя одновременно открыть в Commander и в TCShell. TCShell сообщает, что заблокирован другим процессом, и спрашивает, продолжать ли; сначала закройте workspace в Commander. У многопользовательского workspace с отдельным workspace на каждого клиента этого ограничения нет.
:::

### Скриптовый режим

Подготовьте команды один раз в файле `.tcs` и передайте его путь параметром script; TCShell выполнит его без вопросов. Скрипт в источнике состоит из четырёх строк:

1. Jump to node с путём к ExecutionList, начиная от корня проекта: `Project / Execution / ExecutionLists / PDF compare`.
2. Task: очистить журнал выполнения.
3. Task: запустить ExecutionList.
4. Task: сохранить результаты.

По окончании TCShell печатает каждый шаг и «run finished»; результаты записываются в workspace, так что ExecutionList в Commander показывает новую отметку времени запуска и результат (в источнике failed — ожидаемо для сравнения различающихся PDF). Выполнение из командной строки быстрее, чем из интерфейса, и это единственный способ запустить Tosca из CI/CD-инструмента вроде Jenkins или из планировщика. Если batch-файлу нужно потом ещё и закрыть Commander, см. замечание о `taskkill` в [Запуск и закрытие программ](/ToscaBase/ru/standard-modules/start-and-close-programs/).

## TCWorkspaceUtil: клонирование workspace

### Почему копирование workspace не работает

У каждого workspace есть уникальный ID, созданный вместе с ним. Папка workspace, скопированная на другую машину, сохраняет этот ID, поэтому два процесса Commander обращаются к «одному и тому же» workspace, и он блокируется. Участникам команды нужны клоны, а не копии.

### Клонирование

Инструмент — `TCWorkspaceCloneUtil.exe` в `%COMMANDER_HOME%`. Двойным щелчком его не запустить; вызывайте из командной строки или batch-файла с тремя параметрами:

| Параметр | Значение |
|---|---|
| `-workspace` | Полный путь к клонируемому workspace |
| `-out` | Выходная папка, куда лягут клоны |
| `-count` | Число клонов (в источнике 5; любое число) |

Batch-файл в источнике состоит из двух строк: перейти в каталог `%COMMANDER_HOME%`, затем вызвать исполняемый файл с тремя параметрами. Запуск создаёт по подпапке на клон в выходной папке; каждая — полноценный workspace со своим ID. Скопируйте по одной на машину каждого тестировщика. Все клоны остаются подключёнными к одному репозиторию, так что все делают check-in и check-out над одними данными.

:::note
В названии видео инструмент назван TCWorkspaceUtil; автор и имя файла, которое он ищет, — TCWorkspaceCloneUtil. Ищите в папке установки по «WorkspaceCloneUtil».
:::
