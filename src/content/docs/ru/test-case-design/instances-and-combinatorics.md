**Instance (экземпляр)** — это значение. Экземпляры атрибута — варианты, которые этот атрибут принимает в приложении: у атрибута `Type of user` экземпляры `Registered`, `New`, `Business`, `Technical`. Экземпляры самого TestSheet — это TestCase: каждый выбирает по значению на атрибут и отображается столбцом листа. Tosca умеет создавать такие экземпляры TestCase сама с помощью **комбинаторного метода** — здесь и окупаются техники дизайна из [обзора](/ToscaBase/ru/test-case-design/test-case-design-overview/). Сами атрибуты описаны в [TestSheet и атрибуты](/ToscaBase/ru/test-case-design/test-sheets-and-attributes/).

## Экземпляры атрибута

Правой кнопкой по атрибуту **> Create Instance**, имя — само значение: `Smoke` и `Regression` для `Test cycle`, `1`, `2`, `3` для `Quantity`, `Credit card`, `Internet banking`, `UPI` для `Payment information`, `Success` и `Failure` для проверочного `Message`. У экземпляров не бывает под-экземпляров; вкладываются только атрибуты. Намеренно добавляйте невалидные значения (`Engine performance` = `12000`, когда поле принимает от 1 до 2000): негативные сценарии берутся из невалидных экземпляров.

Добавление экземпляров к атрибутам не меняет число TestCase в листе. Оно меняется, когда вы создаёте экземпляры листа.

## Character и Position

У каждого экземпляра есть два свойства, в которых закодирована техника дизайна. Значения по умолчанию — `Valid` и `Inner`.

**Character (характер)** имеет три значения:

- `Valid`: при использовании этого значения ошибка не ожидается.
- `Invalid`: ошибка ожидается, и она — суть TestCase. Невалидный экземпляр — не TestCase, который «должен упасть»; он проверяет, что приложение корректно отклоняет ввод.
- `Straight through`: счастливый путь. Значение, которое используют большинство клиентов, с минимумом зависимостей, простое в реализации и несущее наибольший бизнес-риск. В демо *Vehicle Insurance* это марка по умолчанию, четыре места, бензин. Straight-through-экземпляры должны проходить всегда; когда времени мало, выполняйте только их — и высокорисковая функциональность покрыта. У каждого атрибута должен быть один straight-through-экземпляр; метод linear expansion (см. ниже) этого требует.

**Position (позиция)** имеет два значения:

- `Boundary`: значение лежит на краю допустимого диапазона. Для количества от 1 до 10 границы — `1` и `10`.
- `Inner`: любое значение внутри диапазона не вплотную к границе, например от `2` до `9`.

Значения вне диапазона (`0`, отрицательные, `11`, `12`) — невалидный ввод; автор урока 53 называет их нижними и верхними граничными значениями, но их характер — `Invalid`.

Свойства задаются в панели свойств или кнопками **Toggle Character** / **Toggle Position** на ленте TestCase-Design при выделенном экземпляре. Toggle Character переключает по кругу `Valid`, `Invalid` и `Straight through`; иконка экземпляра меняется с каждым значением. Когда характер — `Straight through`, Tosca выставляет позицию `Inner` и делает её только для чтения.

## Экземпляры TestSheet: сами TestCase

1. Правой кнопкой по TestSheet **> Create Instance**. Каждый экземпляр листа становится столбцом. Называйте их `Test case 1`, `Test case 2`, ... или, лучше, по id требования, id в Jira или id TestCase; лист вмещает сотни столбцов.
2. В каждом столбце выберите значение для каждого атрибута. Ячейка (или панель деталей) предлагает выпадающий список экземпляров этого атрибута: `Smoke` или `Regression` для цикла, `Registered` или `New` для пользователя, количество, способ оплаты, `Success` или `Failure` для ожидаемого сообщения.
3. Дайте каждому столбцу свой бизнес-поток: один straight-through-случай со значениями счастливого пути, валидные случаи с другими данными, невалидный случай со значением вне диапазона.

Выбранные значения и управляют сгенерированным TestCase: какую `Make` выбрал столбец, ту TestCase и введёт в приложение. Убедитесь, что у каждого атрибута есть значение в каждом столбце.

## Генерация экземпляров комбинаторным методом

Вместо заполнения столбцов вручную щёлкните TestSheet правой кнопкой **> Generate Instances** и выберите метод. Сгенерированные столбцы получают имена из значений экземпляров; при желании переименуйте. Существующие экземпляры можно предварительно выделить и удалить.

| Метод | Что делает | Примеры чисел |
|---|---|---|
| **All combinations** | Все возможные комбинации всех экземпляров всех атрибутов. Максимум TestCase; полно, но обычно невыполнимо. | 3 ручных случая превратились в 972. На листе *Vehicle Insurance* с экземплярами, сгенерированными из Module, запуск остановился: 77 760 экземпляров превышают лимит в 1000. |
| **Orthogonal** | Минимум комбинаций: каждое значение экземпляра используется ровно один раз, при этом в каждом TestCase есть хотя бы одно значение каждого атрибута. | 3 существующих случая плюс 3 сгенерированных, всего 6. |
| **Pairwise** | Каждая пара значений любых двух атрибутов встречается хотя бы в одном TestCase. Больше, чем orthogonal, гораздо меньше, чем all combinations. | 16 TestCase. |
| **Linear expansion** | Отталкивается от straight-through-комбинации и расширяет её. Содержит самые рисковые случаи и даёт оптимальное число — «не слишком много, не слишком мало». Рекомендован Tricentis. | 16 TestCase, примерно как pairwise на том же листе. |

Linear expansion завершается ошибкой, если у какого-то атрибута нет straight-through-экземпляра. Задайте по одному на атрибут (автоматического способа нет — независимо от того, созданы атрибуты вручную или из Module) и запустите снова.

:::note
Лимит в 1000 экземпляров в живой сессии сообщила сама Tosca; ведущий сказал, что это свойство проекта, но не показал где. Тот же ведущий упомянул пятый пункт меню Generate Instances — расширение «на основе концепции relation» — без объяснений. Считайте и то и другое непроверенным.
:::

:::tip
Используйте all combinations только тогда, когда действительно есть время выполнить всё. Для регрессионного листа начните с linear expansion; straight-through-экземпляры, которые он требует, стоит определить в любом случае — именно их вы запускаете первыми перед релизом.
:::
