Этот разбор следует живой сессии, в которой страница *Enter vehicle data* демо-приложения *Vehicle Insurance* проектируется с нуля: TestSheet, атрибуты, экземпляры, комбинаторная генерация, шаблон, инстанцирование, ExecutionList и, наконец, класс. Это практический спутник [Обзора TestCase-Design](/ToscaBase/ru/test-case-design/test-case-design-overview/); каждый шаг ссылается на документ, который его объясняет. Второй разбор, продолжающий то же приложение до условных папок шаблона, — [Разбор: сквозной живой проект](/ToscaBase/ru/troubleshooting/worked-example-live-project/).

## Исходная точка

Компонентная папка содержит разделы для сессии. Страница *Enter vehicle data* уже отсканирована в Module с ModuleAttribute на каждое поле (`Make`, `Engine performance`, `Date of manufacture`, `Number of seats`, `Fuel type`, `License plate number`, ...). В разделе TestCases есть TestCase с этим Module и пустыми значениями. Ничего ещё не спроектировано.

## Шаг 1: лист и атрибуты

1. В разделе TestCase-Design создайте папку, а в ней TestSheet с именем `Vehicle data` (ориентир — один лист на требование). [TestSheet и атрибуты](/ToscaBase/ru/test-case-design/test-sheets-and-attributes/)
2. Создайте атрибут верхнего уровня `Enter vehicle data` и податрибуты для проверяемых полей: `Make`, `Engine performance`, `License plate number`. Атрибут на экран с потомком на поле держит лист в соответствии с приложением.
3. Задайте **Business relevant**: `Make` и `Engine performance` — обязательные поля, значит `Yes`; `License plate number` необязательное — `No`; всё, что проверяет результат, было бы `Result`. Ведущий переключает значение кнопкой **Toggle Business Relevance** и следит за цветом иконки.

## Шаг 2: экземпляры с характером и позицией

1. Дайте `Make` экземпляры `Audi`, `BMW`, `Ford`. [Экземпляры и комбинаторика](/ToscaBase/ru/test-case-design/instances-and-combinatorics/)
2. Дайте `Engine performance` граничные значения `1` и `2000` (поле принимает от 1 до 2000) и выходящее за диапазон `12000`. Невалидное значение добавлено намеренно: негативные сценарии берутся из невалидных экземпляров.
3. Задайте **Character** и **Position**: `1` и `2000` — `Valid`, `12000` — `Invalid` (позиция `Inner`, поскольку это не граница допустимого диапазона). Одно значение на атрибут становится `Straight through`: `Audi` для марки, `2000` для мощности. `1` помечается как `Boundary`; `2000` тоже была бы границей, но как только её характер — `Straight through`, Tosca ставит позицию `Inner` и делает её только для чтения.

:::note
Субтитровый транскрипт один раз называет `2001` значением «на границе», хотя такой экземпляр на экране не создавался. Правило, которое формулирует ведущий, ясно: один straight-through-экземпляр на атрибут, граничные значения помечены как границы.
:::

## Шаг 3: экземпляры TestCase — вручную и генерацией

1. Правой кнопкой по листу **> Create Instance** три раза. Появляются три столбца; в каждом выберите значение на атрибут из выпадающего списка: столбец со всеми straight-through-значениями, столбец с другими валидными значениями, столбец с невалидным `12000`.
2. Удалите три столбца, чтобы попробовать генераторы. **Generate Instances > All combinations** даёт два столбца, если в листе только атрибуты с двумя значениями.
3. Перетащите Module `Enter vehicle data` на лист. Tosca создаёт атрибуты и экземпляры для каждого поля из Module. Исправьте сгенерированные значения там, где они неверны (поля свободного ввода), и заново задайте характер, позицию и бизнес-релевантность.
4. **All combinations** теперь завершается ошибкой: 77 760 экземпляров превышают лимит в 1000. **Orthogonal** даёт минимальный набор — хотя бы одно значение каждого атрибута в каждом столбце. **Pairwise** даёт больше.
5. **Linear expansion** завершается сообщением, что не хватает straight-through-экземпляра. Пометьте по одному на атрибут (вручную; автоматического способа нет) и запустите снова: результат — оптимальный набор, который рекомендует Tricentis.

## Шаг 4: шаблон

1. В разделе TestCases щёлкните TestCase правой кнопкой **> Convert to Template**. Выполнять его больше нельзя. [Шаблоны и инстанцирование](/ToscaBase/ru/test-case-design/templates-and-instantiation/)
2. Перетащите лист `Vehicle data` на шаблон. Свойство шаблона **Schema path** теперь показывает имя листа; **Jump to Schema Definition** открывает лист.
3. Нажмите **Check Template**: `No errors found in template`.
4. Посмотрите на значения TestStep: пустые заполнились ссылками в лист (атрибут и податрибут). Уже заполненные не тронуты; для них перетащите атрибут из листа в значение или наберите ссылку.

## Шаг 5: инстанцирование, выполнение, сопровождение

1. Правой кнопкой по шаблону **> Create Template Instance** (или **Instantiate** на ленте), подтвердите **Start instantiation**. Появляется папка с таким числом TestCase, сколько столбцов в листе; откройте два из них — значения различаются согласно комбинации.
2. В разделе Execution создайте папку и ExecutionList и перетащите в него папку экземпляров: по записи выполнения на TestCase. [Списки выполнения](/ToscaBase/ru/execution/execution-lists/)
3. Измените значение в листе, затем щёлкните папку экземпляров правой кнопкой **> Reinstantiate Instance**. Изменение — в каждом затронутом TestCase.
4. На шаблоне задайте **Instance name** шаблоном, начинающимся с `TC`, и реинстанцируйте; TestCase переименуются по шаблону.

## Шаг 6: класс для общих атрибутов

Те же атрибуты `Enter vehicle data` понадобятся в листах для грузовиков, мотоциклов и кемперов. Перетащите атрибут в папку и выберите **Create class from attribute**; создаётся класс `Enter vehicle data` со всеми податрибутами и экземплярами. В каждом листе удалите локальные атрибуты и перетащите в него класс: лист теперь содержит ссылку на класс только для чтения, а изменения вносятся один раз в классе. [Классы дизайна](/ToscaBase/ru/test-case-design/design-classes/)

## Что остаётся после сессии

- Лист, документирующий сценарий: атрибуты по экранам, значения с характерами valid/invalid/straight-through, помеченные границы.
- Сгенерированный оптимальный набор TestCase вместо написанных вручную, перегенерируемый одним щелчком при изменении данных.
- Ответ на вопрос собеседования «как вы строите TestCase в Tosca»: начать в TestCase-Design с техники дизайна, построить шаблон, инстанцировать. Строить напрямую в разделе TestCases можно, но это использование Tosca как редактора, а не как фреймворка.
