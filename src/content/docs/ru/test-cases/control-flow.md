Обычно TestCase выполняет свои TestStep сверху вниз. Три объекта управления потоком меняют это: оператор **If** выполняет шаги только при выполнении условия, а операторы **While** и **Do** повторяют шаги, пока условие выполняется. Все три создаются из контекстного меню TestCase и содержат часть **Condition** (условие), которую Tosca вычисляет, плюс тело из обычных TestStep. Используйте их для действительно динамических ситуаций; для простого счёта проще свойство [Repetition](/ToscaBase/ru/test-cases/repetitions/) папки, а почему циклы должны быть исключением, Tricentis объясняет в [Структуре TestCase](/ToscaBase/ru/best-practices/test-case-structure/).

## Оператор If

### Какую проблему решает

Страница магазина показывает кнопку `Add to cart` у каждого товара. Как только товар в корзине, кнопка становится `Remove`. TestCase, кликающий `Add to cart`, падает, если товар уже в корзине: лог говорит, что кнопка с заданными свойствами не найдена, что верно, но иногда нужно, чтобы TestCase обработал ситуацию, а не упал. Проверка наличия контрола перед действием — одна из самых частых потребностей в UI-автоматизации.

### Создание

1. Щёлкните правой кнопкой по TestCase (или папке в нём) и выберите **Create If statement**. Tosca добавит объект `If` с частями **Condition** и **Then**.
2. Перетащите объект в нужное место потока, например после шагов логина.
3. Поместите проверку в **Condition**: TestStep на кнопке `Add to cart` с ActionMode `Verify` и значением `Enabled == True` (вместо `Input` с кликом).
4. Поместите действие в **Then**: TestStep, кликающий ту же кнопку через `X` и `Input`.

### Как выполняется

- Условие не выполнено (кнопки нет): шаг условия показывает крестик в результате, часть **Then** пропускается, и TestCase **проходит**. Невыполненное условие — не упавший TestCase.
- Условие выполнено (состояние приложения сброшено, кнопка снова есть): условие показывает галочку, часть **Then** выполняется и кликает кнопку.

Оба исхода видны при раскрытии узла `If` в результате ScratchBook или ExecutionList.

:::note
Автор называет объект «if else step», но демонстрация показывает только части **Condition** и **Then** и никогда не добавляет ветку **Else**. Проверьте в своей версии Tosca, как добавляется часть Else.
:::

Условие не обязано быть проверкой контрола. **TBox Evaluation Tool** может вычислить выражение, например сравнение буферов, что превращает `If` в ветвление по данным; см. [TBox Evaluation Tool](/ToscaBase/ru/standard-modules/evaluation-tool/) с примером из нескольких `If`, эмулирующим `switch`.

## Оператор While

`While` сначала проверяет условие; если оно выполнено, выполняются TestStep в части **Loop**, затем условие проверяется снова — и так, пока оно не перестанет выполняться. Если условие ложно с самого начала, тело цикла не выполнится ни разу.

### Пример: счёт до пяти

Поток: установить буфер-счётчик в 0; пока счётчик меньше 5, прибавлять 1.

1. Добавьте **TBox Set Buffer** с именем буфера `R` и значением `0`. Переименуйте шаг в `Set repetition`. (Буферы объяснены в [Буферах](/ToscaBase/ru/data-and-parameters/buffers/).)
2. Щёлкните правой кнопкой по TestCase и выберите **Create While statement**. Tosca добавит объект `While` с частями **Condition** и **Loop**.
3. В **Condition** добавьте **TBox Evaluation Tool** с выражением `{B[R]} < 5`. Переименуйте в `Check repetition less than 5`.
4. В **Loop** добавьте ещё один **TBox Set Buffer** для `R`, значение которого — математическое выражение, прибавляющее 1 к `{B[R]}`. Переименуйте в `Calculate repetition`.

Запустите в ScratchBook: результат показывает, что условие пять раз вычислилось в true, вычисление выполнялось на каждом проходе, а на шестой проверке `5 < 5` дало false, и выполнение вышло из цикла.

:::note
Автор вводит в значение Set Buffer «функцию math», но не проговаривает синтаксис. Математические выражения описаны в разделе [Выражения](/ToscaBase/ru/expressions/).
:::

:::caution
Имена буферов в выражениях чувствительны к регистру. В источнике буфер случайно переименовали вместе с TestStep, и выражение `{B[R]}` перестало совпадать, пока имя буфера не вернули в `R`.
:::

### Maximum repetitions

У каждого объекта `While` (и `Do`) есть свойство **Maximum repetitions** в панели свойств, ограничивающее число итераций, чтобы неверное условие не зациклилось навсегда. По умолчанию `30`; меняйте, когда циклу законно нужно больше проходов.

## Оператор Do (Do-While)

`Do` повторяет часть **Loop**, пока условие не перестанет выполняться, точно как `While`, с одним отличием: тело выполняется **до** проверки условия, поэтому оно выполнится хотя бы раз, даже если условие никогда не истинно.

1. Щёлкните правой кнопкой и выберите **Create Do statement** или нажмите **Ctrl+N**, затем **Ctrl+D**. Tosca добавит объект `Do` с частями **Loop** и **Condition**.
2. Скопируйте те же шаги `Set repetition`, `Calculate repetition` и `Check repetition` из примера с `While`: вычисление идёт в **Loop**, проверка — в **Condition**.

Прогон сначала вычисляет, потом проверяет; повторяет, пока выражение не станет ложным (`5 < 5` на последнем проходе), и переходит к следующему TestStep. Из-за обратного порядка число итераций для одного и того же условия у `While` и `Do` различается, так что выбирайте по тому, должно ли тело выполниться хотя бы раз. **Maximum repetitions** относится и к `Do`, с тем же значением по умолчанию 30.

## Что выбрать

| Задача | Использовать |
|---|---|
| Выполнить шаги только если контрол есть или значение совпадает | `If` |
| Повторять, пока что-то истинно, возможно ноль раз | `While` |
| Повторить хотя бы раз, потом проверить | `Do` |
| Повторить фиксированное число раз | Свойство [Repetition](/ToscaBase/ru/test-cases/repetitions/) папки, без цикла |
| Найти строку таблицы по содержимому | ActionMode `Constraint`, без цикла; см. [Режимы действия](/ToscaBase/ru/test-cases/action-modes/) |
| Реагировать на сбой, а не на условие | [Сценарии восстановления и очистки](/ToscaBase/ru/test-cases/recovery-and-cleanup-scenarios/) |
