Обычно TestCase выполняет свои TestStep сверху вниз. Три объекта управления потоком меняют это: оператор **If** выполняет шаги только при выполнении условия, а операторы **While** и **Do** повторяют шаги, пока условие выполняется. Все три создаются из контекстного меню TestCase; дочерние объекты (часть **Condition** (условие), которую Tosca вычисляет, плюс части с обычными TestStep) Tosca добавляет сама. Условие — это обычно `Verify` на контроле (`Exists`, `Visible`, `Enabled`) или выражение **TBox Evaluation Tool** над буферами, и условие, давшее false, — это решение о ветвлении, а не упавший TestCase. Используйте эти объекты для действительно динамических ситуаций; для простого счёта проще свойство [Repetition](/ToscaBase/ru/test-cases/repetitions/) папки, а почему циклы должны быть исключением, Tricentis объясняет в [Структуре TestCase](/ToscaBase/ru/best-practices/test-case-structure/).

## Оператор If

### Какую проблему решает

Страница магазина показывает кнопку `Add to cart` у каждого товара; как только товар в корзине, кнопка становится `Remove`. TestCase, кликающий `Add to cart`, падает, если товар уже там, — это верно, но часто нужно, чтобы TestCase обработал ситуацию. То же со страницей логина, которую предыдущий прогон оставил залогиненной. Проверка состояния перед действием — одна из самых частых потребностей в UI-автоматизации.

### Создание

1. Щёлкните правой кнопкой по TestCase (или папке в нём) и выберите **Create If statement**. Tosca добавит объект `If` с частями **Condition** и **Then**; порядок всегда If, Condition, Then.
2. Если нужна вторая ветка, щёлкните правой кнопкой по объекту `If` и выберите **Create Else statement**. Часть **Then** показана значком со стрелкой влево, часть **Else** — со стрелкой вправо, и Else всегда идёт последней.
3. Перетащите объект в нужное место потока.
4. Поместите проверку в **Condition**: TestStep с ActionMode `Verify`, например `Enabled == True` на `Add to cart` или `Visible == True` на ссылке `Login`.
5. Поместите действия в **Then**, а альтернативу — в **Else**.

:::caution
Шаг условия должен использовать `Verify`. В уроке 27 его сначала оставили с `Input`, прогон попытался ввести текст в ссылку, и его пришлось остановить; смена ActionMode всё исправила.
:::

### Как выполняется

- Условие выполнено: условие показывает галочку, шаги **Then** выполняются один раз, **Else** пропускается.
- Условие не выполнено: условие показывает крестик, **Then** пропускается, шаги **Else** (если есть) выполняются один раз, и TestCase **проходит**.

Оба исхода видны при раскрытии узла `If` в результате ScratchBook или ExecutionList. Пример с логином из урока 27 показывает оба: **Condition** проверяет, что `Login` в верхнем меню видна; **Then** кликает `Login` и вводит учётные данные; **Else** кликает `Logout`, затем `Login`, затем вводит учётные данные. На свежем браузере выполняется ветка Then; при повторном запуске без выхода условие не выполняется, ветка Else выходит и входит заново, и TestCase всё равно проходит.

Условие не обязано быть проверкой контрола. **TBox Evaluation Tool** может вычислить выражение, например сравнение буферов, что превращает `If` в ветвление по данным; см. [TBox Evaluation Tool](/ToscaBase/ru/standard-modules/evaluation-tool/) с примером из нескольких `If`, эмулирующим `switch`.

## Оператор While

**Create While statement** добавляет объект `While` с частями **Condition** и **Loop**, в этом порядке. Tosca сначала проверяет условие; если оно выполнено, выполняются TestStep в **Loop**, затем условие проверяется снова — и так, пока оно не перестанет выполняться. Если условие ложно с самого начала, тело цикла не выполнится ни разу.

### Пример: счёт до пяти

Установить буфер-счётчик в 0; пока счётчик меньше 5, прибавлять 1.

1. Добавьте **TBox Set Buffer** с именем буфера `R` и значением `0`; переименуйте шаг в `Set repetition`. (Буферы объяснены в [Буферах](/ToscaBase/ru/data-and-parameters/buffers/).)
2. Создайте `While`. В **Condition** добавьте **TBox Evaluation Tool** с выражением `{B[R]} < 5`.
3. В **Loop** добавьте ещё один **TBox Set Buffer** для `R` со значением `{MATH[{B[R]}+1]}` — математическое выражение, прибавляющее 1 к текущему значению буфера (синтаксис — в [Строковых операциях](/ToscaBase/ru/expressions/string-operations/)).

В ScratchBook условие пять раз вычисляется в true, вычисление выполняется на каждом проходе, а на шестой проверке `5 < 5` даёт false, и выполнение выходит из цикла.

:::caution
Имена буферов в выражениях чувствительны к регистру. В источнике буфер случайно переименовали вместе с TestStep, и `{B[R]}` перестало совпадать, пока имя не вернули в `R`.
:::

### Пример: опустошать корзину, пока таблица не исчезнет

Повседневный `While` повторяет действие, пока контрол не исчезнет. Уроки 19 и 29 строят его как переиспользуемый TestStepBlock в TestStepLibrary, потому что каждому TestCase нужна пустая корзина на старте (см. [Business Parameters и библиотеки TestStep](/ToscaBase/ru/data-and-parameters/business-parameters-and-libraries/)): клик по корзине (`X`), `While`, клик `Logout`, `WaitOn` `Visible == True` на ссылке `Login`, `Close Browser` с заголовком `Demo*`.

- **Condition:** узел таблицы Module корзины, `Exists == True`, ActionMode `Verify`. Таблица корзины существует, только пока в корзине есть товары.
- **Loop:** тот же Module; строка `$1`, колонка `Remove`, чекбокс `Input` `True`; затем `Update shopping cart` через `X`. Каждый проход удаляет первую оставшуюся строку.

С четырьмя товарами цикл выполняется четыре раза; пятая проверка не находит таблицу, условие ложно, и выполнение продолжается выходом из системы. Последняя запись условия в логе гласит: ожидаемое `True`, фактическое `False` — это выход из цикла, а не ошибка. Табличные селекторы объяснены в [Табличных контролах](/ToscaBase/ru/modules/table-controls/).

### Maximum repetitions

У каждого объекта `While` (и `Do`) есть свойство **Maximum repetitions**, ограничивающее число итераций, чтобы условие, которое никогда не станет ложным, не зациклилось навсегда. По умолчанию `30`, значение показано в колонке Value объекта и в его свойствах; меняйте, когда циклу законно нужно больше проходов.

## Оператор Do (Do-While)

**Create Do statement** (или **Ctrl+N**, **Ctrl+D**) добавляет объект `Do` с частью **Loop**, за которой идёт **Condition**. Он повторяет **Loop**, пока условие не перестанет выполняться, точно как `While`, с одним отличием: тело выполняется **до** проверки условия, поэтому оно выполнится хотя бы раз, даже если условие никогда не истинно. **Maximum repetitions** действует с тем же значением по умолчанию 30.

- Пример со счётчиком превращается в `Do` переносом шага `Calculate repetition` в **Loop**, а проверки — в **Condition**: прогон сначала вычисляет, потом проверяет, и останавливается, когда `5 < 5` ложно. Из-за обратного порядка число итераций для одного условия у `While` и `Do` различается.
- Урок 28 опустошает корзину через `Do`: **Loop** отмечает чекбокс `Remove` строки `$1` и кликает `Update shopping cart`, **Condition** проверяет, что таблица корзины всё ещё `Exists`. После четвёртого удаления проверка не проходит, и выполнение выходит из цикла. Поскольку тело выполняется первым, этот вариант предполагает, что корзина не пуста; если она может быть пустой, используйте вариант с `While`.

## Что выбрать

| Задача | Использовать |
|---|---|
| Выполнить шаги только если контрол есть или значение совпадает, с альтернативой | `If` с `Then` и `Else` |
| Повторять, пока что-то истинно, возможно ноль раз | `While` |
| Повторить хотя бы раз, потом проверить | `Do` |
| Повторить фиксированное или вычисленное число раз | Свойство [Repetition](/ToscaBase/ru/test-cases/repetitions/) папки, без цикла |
| Найти строку таблицы по содержимому | ActionMode `Constraint`, без цикла; см. [Режимы действия](/ToscaBase/ru/test-cases/action-modes/) |
| Реагировать на сбой, а не на условие | [Сценарии восстановления и очистки](/ToscaBase/ru/test-cases/recovery-and-cleanup-scenarios/) |
