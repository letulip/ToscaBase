Исследовательское тестирование (exploratory testing) — это одновременное изучение, проектирование тестов и выполнение: заранее написанных TestCase нет, тестировщик исследует систему на ходу, чтобы найти дефекты, которые скриптовые тесты пропускают. Это ad hoc, но не случайное тестирование. Tosca поддерживает его через **explorative session** (исследовательские сессии), которые планируют и ограничивают работу по времени, и рекордер, превращающий сессию в пошаговый **документ сценария** со скриншотами, экспортируемый в PDF. Этот документ полезен далеко за пределами исследовательского тестирования: как отчёт об ошибке для разработчика, как пошаговое руководство для нового участника команды или как основа для вопросов бизнес-аналитику.

## Explorative session

1. В секции **Execution** раскройте папку **Exploratory Testing**.
2. Её контекстное меню предлагает **Create explorative session**, **Create folder**, **Import results file** и **Import results from session ID**. Выберите **Create explorative session**.

Сессия хранит данные планирования одного раунда исследования:

| Поле | Назначение |
|---|---|
| Exploratory testers | Кто участвует |
| Issue proposals | Проблемы, поднятые в ходе сессии |
| Scenario link и description | О чём сессия |
| Session schedule | Временное окно от начала до конца |
| Session owner | Администратор сессии |
| Status | `Planned` при создании; позже passed или failed |
| Scenarios, duration, objects, email | Счётчики и контактные данные, заполняемые по ходу сессии |

## Запись сценария

Ядро сессии — документ сценария, создаваемый через **Explorative Scenario Manager**.

1. Откройте Explorative Scenario Manager из сессии и нажмите **Explorative scenario** на его верхней панели.
2. Выберите тип записываемого приложения; для веб-приложения выберите **Chrome**. Нажмите **Start**.
3. Взаимодействуйте с приложением: откройте страницу, заполните поля, выберите значения в выпадающих списках. Каждое взаимодействие фиксируется в фоне.
4. Нажмите **Stop**. Tosca соберёт документ сценария.

Документ — медиадокумент: слева **шаги сценария** текстом (например *click on Automobile*, *click the drop-down and select the value*); справа — скриншот всего экрана на каждый шаг с аннотированным взаимодействием. Человек, никогда не видевший приложение, может пройти по нему шаг за шагом и отметить каждый сценарий как пройденный или упавший.

**Save and close** сохраняет сценарий в сессии и позволяет перейти к следующему.

## Экспорт документа

Документ сессии экспортируется в **DOCX** или **PDF**; автор рекомендует PDF.

1. Выберите экспорт и отметьте, что включить: **steps and step values**, дополнительные колонки (**actual result**, **ActionMode**, **action property**), **media** (включено по умолчанию) и **page setup**.
2. Укажите целевую папку и нажмите **OK**.

Экспортированный PDF содержит больше, чем было записано:

- **Summary**: имя, общий результат, число упавших шагов, число шагов.
- **Scenario description** с каждым шагом.
- **Media**: скриншоты по порядку, которые читаются как видео взаимодействия.
- **System information**: операционная система, разрешение экрана и другие детали машины — полезно при воспроизведении проблемы.
- **Recorded applications** с версиями.

## Рекордер или исследовательское тестирование?

Оба записывают, что вы делаете в приложении, но для разного результата. [Рекордер](/ToscaBase/ru/test-cases/recorder/) генерирует Module и исполняемый TestCase; Explorative Scenario Manager генерирует читаемый человеком документ со скриншотами и без объектов автоматизации. Первый — чтобы автоматизировать, второй — чтобы задокументировать, отчитаться или передать.

:::note
Источник охватывает только explorative session, запись и экспорт. Автор упоминает, что в области исследовательского тестирования есть и другие опции, и оставляет их на потом; здесь они не описаны.
:::
