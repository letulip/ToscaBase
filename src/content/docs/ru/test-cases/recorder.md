Обычный способ построить TestCase - отсканировать Module через [XScan](/ToscaBase/ru/modules/xscan/) и собрать из них TestStep. **Recorder** (рекордер) предлагает короткий путь: вы проходите сценарий в приложении, а Tosca создаёт Module и TestCase для каждого действия, включая верификации. Это самый быстрый путь к работающему TestCase, но не самый чистый, поэтому он подходит для двух ситуаций: проверка осуществимости - может ли Tosca вообще управлять данным приложением - и небольшие приложения, которым нужна быстрая автоматизация. Для настоящего регрессионного набора предпочтительным остаётся сканирование собственных Module и самостоятельное структурирование.

## Запуск записи

Recorder - последняя опция на панели меню **Home**. У неё два пункта:

- **Automated TestCase** записывает обычный TestCase.
- **Automated data-driven TestCase** записывает то же самое плюс TestSheet, чтобы TestCase можно было управлять данными (см. [TestSheet и атрибуты](/ToscaBase/ru/test-case-design/test-sheets-and-attributes/)).

Клик по самому значку Recorder или по одному из пунктов загружает рекордер: появляется небольшая панель, а красные метки в четырёх углах экрана показывают, что записывается весь экран.

## Панель рекордера

| Элемент | Что делает |
|---|---|
| Settings | Показывает все настройки рекордера (см. ниже) |
| Image-based TestStep | Переключает на идентификацию контрола по изображению для следующего шага; **Esc** возвращает в обычный режим. Тот же механизм, что и идентификация по изображению в [Идентификации контролов](/ToscaBase/ru/modules/control-identification/) |
| Verification mode (значок галочки, **Ctrl+Shift+V**) | Пока включён, клик по контролу добавляет шаг `Verify` для него вместо действия |
| Pause | Приостанавливает запись, например пока вы переходите куда-то, что записывать не нужно |
| Stop and save | Завершает запись и генерирует объекты |

Подсказки во время записи показывают ещё горячие клавиши: **Ctrl+Shift+H** записывает событие наведения мыши, **F5** обновляет рекордер.

### Настройки

- **Auto record mouse over** (по умолчанию выключено).
- **Hints** - подсказки вкл./выкл.
- **Reuse existing Modules** - чтобы запись не создавала дубликаты уже имеющихся Module.
- **Block processes** - исключить процессы из записи.
- Горячие клавиши для смены режима записи, записи наведения мыши и обновления рекордера.

## Рабочий пример: оформление заказа в интернет-магазине

Выбран **Automated TestCase**: клик `Login`, ввод email и пароля, клик `Login`; открыть товар и добавить в корзину; открыть корзину и пройти оформление (адрес выставления счёта, адрес доставки, способ доставки, оплата), нажимая **Continue** до страницы подтверждения и **Confirm**. На странице подтверждения нажать **Ctrl+Shift+V**, кликнуть номер заказа, чтобы записать верификацию, выключить режим верификации, продолжить и кликнуть `Logout`. Затем **Stop and save**.

Tosca создаёт в проекте новую папку, содержащую:

- **По одному Module на страницу** с ModuleAttribute для каждого использованного контрола, с именами по умолчанию от Tosca.
- **Один TestCase** с TestStep на каждое записанное действие. Клик записывается как значение `X` с ActionMode `Input`, набранный текст - как текст с `Input`, а верификация - как `Verify` на `InnerText` кликнутого контрола.

## Что дорабатывать потом

Записанный TestCase запускается, но не закончен:

- **Переименуйте** Module, ModuleAttribute и TestStep по вашим [соглашениям об именовании](/ToscaBase/ru/best-practices/naming-conventions/); сгенерированные имена ничего не описывают.
- **Удалите дубликаты.** Несколько кликов по контролу во время записи дают несколько шагов; в источнике номер заказа проверялся трижды, и два шага пришлось убрать.
- **Замените статические значения.** Записанная верификация сравнивает с литеральным номером заказа, увиденным при записи, а он меняется с каждым заказом. Буферизуйте его или проверяйте шаблон; см. [Режимы действия](/ToscaBase/ru/test-cases/action-modes/) и [Интервалы и выражения проверки](/ToscaBase/ru/expressions/intervals-and-verification-expressions/).
- **Реструктурируйте** в папки и переиспользуемые шаги, как описано в [Структуре TestCase](/ToscaBase/ru/best-practices/test-case-structure/).

Компромисс - время: запись сквозного сценария занимает несколько минут, сканирование каждого Module отдельно - дольше; цена - сгенерированные имена и структура, которую вы бы не выбрали сами. Чтобы задокументировать ручную сессию скриншотами, а не сгенерировать TestCase, используйте рекордер [исследовательского тестирования](/ToscaBase/ru/test-cases/exploratory-testing/).
