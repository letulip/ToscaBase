ActionMode (режим действия) говорит Tosca, как применить **Value** (значение) TestStepValue к управляемому контролу: ввести, сравнить, сохранить, дождаться или использовать для сужения поиска. У каждого TestStepValue ровно один ActionMode, выбираемый из выпадающего списка в TestStep. Какие ActionMode доступны, зависит от типа интерфейса Module (GUI или не-GUI). Эта страница — справочник по всем семи; окружающие понятия описаны в [Основах TestCase](/ToscaBase/ru/test-cases/test-case-basics/).

## Сводная таблица

| ActionMode | Что делает со значением | Типичное применение | Примечания |
|---|---|---|---|
| `Input` | Вводит значение в контрол или кликает по нему | Текстовые поля, выпадающие списки, радиокнопки, кнопки, ссылки | По умолчанию для полей ввода и кликабельных контролов |
| `Insert` | Создаёт объект в не-UI структуре | XML и другие не-GUI интерфейсы | Недоступен для GUI Module |
| `Verify` | Сравнивает свойство контрола со значением | Точки проверки | Логируется с ожидаемым и фактическим значением |
| `Buffer` | Сохраняет значение контрола под именем буфера, указанным в Value | Переиспользование значений позже в том же или другом TestCase | Value — это имя буфера; см. [Буферы](/ToscaBase/ru/data-and-parameters/buffers/) |
| `WaitOn` | Ждёт, пока условие в Value не станет истинным | Динамическая синхронизация | Ограничен таймаутом в настройках; показан на жёлтом фоне |
| `Select` | Выбирает узел в иерархии | Узлы таблицы, строки и колонки | Tosca ставит автоматически на пути к ячейке |
| `Constraint` | Ограничивает поиск под вышестоящим узлом элементами, соответствующими значению | Выбор строки таблицы по содержимому ячейки | Комбинируйте несколько, чтобы совпадение было уникальным |

## Input

`Input` — ActionMode, который Tosca подставляет для любого поля ввода или кликабельного контрола. Что писать в Value, зависит от контрола:

- **Текстовое поле.** Вводимый текст.
- **Выпадающий список.** Одно из значений из списка ModuleAttribute; XScan захватывает варианты при сканировании Module, так что вы выбираете из них, а не печатаете.
- **Радиокнопка, чекбокс.** Устанавливаемое состояние.
- **Кнопка или ссылка.** `X` выполняет клик внутренне, без перемещения указателя. `{CLICK}` выполняет физический клик мышью с движением курсора. Предпочитайте `X`; почему — см. [Синхронизация вместо ожиданий](/ToscaBase/ru/best-practices/synchronisation-not-waits/).

Значения могут быть выражениями, а не литералами: случайные значения, даты, строковые операции и буферы `{B[name]}` — всё это допустимый ввод. См. раздел [Выражения](/ToscaBase/ru/expressions/).

## Insert

`Insert` существует только для не-UI интерфейсов; GUI Module его не предлагают. Он создаёт объекты внутри структуры вроде XML-документа. Случай XML описан в [Движок XML](/ToscaBase/ru/engines/xml-engine/).

## Verify

`Verify` сравнивает свойство контрола с ожидаемым значением. Выпадающий список Value показывает доступные свойства (`Exists`, `Enabled`, `Visible`, `InnerText` и другие), а вы дописываете условие, например:

- `Exists == True` проверяет, что контрол есть на странице.
- `Enabled == True` проверяет, что кнопка кликабельна.
- `InnerText == jane@example.com` проверяет отображаемый текст ссылки или ячейки.

Если условие выполнено, TestStepValue проходит; иначе TestStep и TestCase падают. В ExecutionLog появляется запись о верификации с ожидаемым и фактическим значением, и такую запись дают только шаги `Verify` — одна из причин, почему каждый TestCase должен содержать хотя бы один (см. [Структура TestCase](/ToscaBase/ru/best-practices/test-case-structure/)). Проверка по интервалам, регулярным выражениям и многоязычным альтернативам описана в [Интервалах и выражениях проверки](/ToscaBase/ru/expressions/intervals-and-verification-expressions/).

## Buffer

`Buffer` сохраняет текущее значение контрола под именем буфера, указанным в Value. Поставьте ActionMode, замените подставленное Tosca имя контрола на нужное имя буфера (например `email`) — и при выполнении Tosca прочитает контрол, запишет значение в этот буфер и сообщит об этом в логе. Читайте его где угодно выражением `{B[email]}`, в том же TestCase или в другом. Чтобы за один шаг проверить значение и сохранить его меняющуюся часть, поставьте `{XB[name]}` внутрь значения `Verify`.

Этот ActionMode — лишь один из способов создать буфер; как буферы создаются, читаются, где действуют и как их смотреть в Buffer Viewer, включая `{XB[...]}`, описано в [Буферах](/ToscaBase/ru/data-and-parameters/buffers/).

## WaitOn

`WaitOn` — динамическое ожидание Tosca: прерывает выполнение, пока свойство, названное в Value, не примет указанное значение, и сразу продолжает. Tricentis рекомендует его всегда, когда вы ждёте условия в приложении или ещё не видимого контрола, вместо статического `TBox Wait`, который всегда ждёт полную длительность и замедляет каждый прогон.

- Value — условие вроде `Enabled == True` или `Exists == True`.
- TestStepValue с `WaitOn` показан на жёлтом фоне.
- Максимальное ожидание — **Settings > TBox > Synchronization > Synchronization timeout during WaitOn**, по умолчанию 20000 мс; увеличивайте или уменьшайте по необходимости. Если условие не выполнено за таймаут, шаг падает.

Классический пример — кнопка `Send`, которая становится доступной только когда заполнится индикатор прогресса, запущенный кнопкой `Calculate`, — разобран в статическом и в `WaitOn`-варианте в [Синхронизации вместо ожиданий](/ToscaBase/ru/best-practices/synchronisation-not-waits/).

## Select

`Select` выбирает конкретный узел в иерархии. Вручную его ставят редко: когда управляют отсканированной таблицей, Tosca автоматически назначает `Select` узлу таблицы и узлу строки на пути вниз к ячейке. Строка выбирается через `$1` для первой, `$last` для последней или `$n` для строки *n*; колонки адресуются по заголовкам, захваченным XScan. Сторону Module и полный список селекторов см. в [Табличных контролах](/ToscaBase/ru/modules/table-controls/).

## Constraint

`Constraint` ограничивает поиск под вышестоящим узлом (обычно строкой таблицы) элементами, чьё значение совпадает. Вместо перебора строк и сравнения ячеек вы объявляете, какие значения ячеек идентифицируют строку, и Tosca находит её напрямую; на сотнях строк это ещё и намного быстрее. На одной строке можно комбинировать любое число Constraint, и нужно столько, сколько требуется для уникального совпадения: если у двух строк `First name` = `John`, один Constraint падает, потому что строка не уникальна; добавьте второе на `Last name` = `Doe` — и строка найдена.

Внутри одного TestStep схема всегда одна: `Select` (автоматически) на таблице и строке, `Constraint` на идентифицирующей ячейке (`InnerText == Jane`), затем `Verify` (`InnerText == jane@example.com`), `Buffer` или `Input` на целевой ячейке. Constraint плюс `Verify` проверяет; Constraint плюс `Buffer` извлекает. Рабочие примеры на таблицах, включая селектор `#n` для *n*-й подходящей строки, — в [Табличных контролах](/ToscaBase/ru/modules/table-controls/); перемешанные строки и другие проблемные таблицы — в [Препятствиях: таблицы](/ToscaBase/ru/troubleshooting/obstacles-tables/).

## Выбор ActionMode

- Нужно воздействовать на приложение: `Input` (GUI) или `Insert` (не-GUI).
- Нужно доказать, что действие выполнилось: `Verify`.
- Значение понадобится позже: `Buffer`; нужно и то и другое сразу: `Verify` с `{XB[...]}`.
- Нужно дождаться приложения: `WaitOn`, никогда не статическое ожидание.
- Работа внутри таблицы: `Select` (автоматически) до строки, `Constraint` для её выбора, затем `Verify`, `Buffer` или `Input` на целевой ячейке.

Смешивать ActionMode в одном TestStep — норма; табличная схема использует `Select`, `Constraint` и `Verify` вместе.
