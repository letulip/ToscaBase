В Tosca три уровня отчётности. **Print View** за секунды выгружает то, что на экране, в документ. Раздел **Reporting** поставляется со стандартными report definition (определениями отчётов), которые превращают ExecutionList (список выполнения), набор TestCase (тест-кейсов) или requirement set в оформленный отчёт со сводкой, круговой диаграммой, логами и скриншотами. А собственное **определение отчёта** позволяет точно выбрать, какие объекты (через TQL-запрос) и в каком оформлении (стандартный дизайнер, XML или Excel) попадут в документ.

## Print View: быстрый снимок

1. Выделите объект или папку и раскройте то, что хотите видеть (например, ExecutionList со всеми записями).
2. Нажмите **Print View**, выберите формат: PDF, Word, Excel или HTML.
3. Нажмите **Start**. Tosca создаст файл и откроет его (HTML откроется в браузере).

Результат — точный снимок представления Commander: не красиво, зато мгновенно. Работает в любом разделе, включая [дашборд требований](/ToscaBase/ru/requirements-and-reporting/requirements-and-risk/).

## Раздел Reporting и стандартные определения

Если раздел **Reporting** не виден, откройте его через меню **Sections > Reporting**. В нём перечислены стандартные определения отчётов и data definition (определения данных), поставляемые Tosca:

- отчёты по ExecutionList: **Execution entries with actual log** и **Execution entries with detailed logs**;
- отчёт по требованиям;
- отчёт по TestCase.

Каждый состоит из определения отчёта (оформление) и определения набора данных (какие объекты выбрать).

### Печать стандартного отчёта

1. Правой кнопкой по ExecutionList, папке ExecutionList, папке TestCase или requirement set **> Print Report**. Предлагаются только определения, подходящие этому типу объекта.
2. Выберите определение, например **Execution entries with detailed logs**. Снова откроется диалог печати, но вывод теперь следует определению, а не экрану.
3. Нажмите **Start**, сохраните файл и ответьте на вопросы: показывать ли только упавшие TestCase (ответьте No, чтобы включить всё) и включать ли скриншоты (Yes).

Отчёт содержит шапку с логотипом Tricentis (его можно заменить в разделе Reporting), дату создания, сводку с круговой диаграммой (например, 19 TestCase: 3 passed, 14 no result, 2 failed), затем блок на каждый ExecutionList и запись с каждым TestStep, временем начала и окончания, исполнителем, логом и скриншотом там, где шаг упал. Одинаково работает и для одного [бизнес-TestCase](/ToscaBase/ru/execution/execution-repetitions-and-business-test-cases/), и для целой папки [ExecutionList](/ToscaBase/ru/execution/execution-lists/).

## Создание собственного определения отчёта

1. Правой кнопкой по папке **Reporting > Create Report Definition**. Новое определение помечено восклицательным знаком: оно ещё не настроено.
2. **Назначьте определение набора данных и тип объекта.** Перетащите объект того типа, по которому нужен отчёт (ExecutionList, TestCase, требование, Module), на определение отчёта. Ссылка задаёт тип объекта определения, например `ExecutionList`. Восклицательный знак остаётся, потому что ещё нет дизайнера.
3. **Создайте designer definition (определение дизайнера).** Правой кнопкой по определению **> Create Designer Definition** и выберите один из трёх вариантов:
   - **Default**: открывает отчёт в Report Designer, встроенном стороннем инструменте, где правят тексты, колонтитулы и логотип.
   - **XML report**: XML-документ со всей сгенерированной информацией.
   - **Excel report**: лист Microsoft Excel на каждое определение данных.

   После назначения дизайнера восклицательный знак исчезает. Результат теперь похож на встроенное определение «Execution entries with actual log».
4. **Укажите набору данных, какие объекты выбирать.** Одного типа объекта недостаточно. Создайте ещё одно определение набора данных и задайте ему [TQL-запрос](/ToscaBase/ru/requirements-and-reporting/tql-and-virtual-folders/), который найдёт объекты в workspace. Либо впишите запрос в столбец **TQL query** (если скрыт, добавьте через **Column Chooser**), либо соберите его из полей **Link**, **Object type** и **Constraint**. Например: link `SubParts`, тип объекта `ExecutionList`, ограничение `Name=="End to end scenario"`. Tosca собирает TQL-запрос по мере заполнения полей.
5. Правой кнопкой по целевому объекту **> Print Report** и выберите своё определение.

:::tip
Для ExecutionList, папки TestCase или requirement set обычно хватает стандартных определений. Собственное определение стоит делать только при нужной выборке объектов (через TQL или [виртуальную папку](/ToscaBase/ru/requirements-and-reporting/tql-and-virtual-folders/)) или фирменном оформлении.
:::
