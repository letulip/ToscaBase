Tosca Query Language (TQL, язык запросов Tosca) — собственная грамматика запросов Tosca для поиска по workspace по типу объекта и свойствам, а не только по тексту. Запрос TQL возвращает все подходящие объекты (TestCase, Module, требования, ExecutionList, TestStepValue и т. д.). **Virtual folder** (виртуальная папка) хранит такой запрос и показывает его результаты как содержимое папки, так что часто нужное представление — например «ExecutionList без падений» или «TestCase, созданные определённым пользователем» — доступно в один клик и может стать источником [отчёта](/ToscaBase/ru/requirements-and-reporting/reports/).

## Окно поиска

Откройте **Search** в верхнем меню. В одном окне собраны оба режима поиска и кнопка сохранения текущего TQL-запроса в виртуальную папку справа.

- **Simple search** (простой поиск): введите текст, и Tosca вернёт все объекты, которые его содержат. Настраивать нечего.
- **TQL search**: простой поиск преобразуется в выражение TQL, которое можно редактировать. Здесь в игру вступают свойства и операторы.

## Как строится запрос TQL

Запрос — это цепочка подвыражений:

1. **Область**: где искать. `SubParts` от текущей папки возвращает всё, что под ней; от корня проекта — весь workspace.
2. **Тип объекта**: какой класс объектов вернуть, например `ExecutionList`, `TestCase`, `Requirement`, `Module`.
3. **Ограничение** в квадратных скобках: логическое сравнение свойства со значением.

Операторы из урока:

| Оператор | Значение | Пример |
|---|---|---|
| `=?` | содержит текст (то, что генерирует простой поиск) | `Name=?"Google"` |
| `==` | точное совпадение, результатов заметно меньше | `Name=="Google"`, `CreatedBy=="Admin"` |
| `>` | больше | `NumberOfTestCasesPassed>1` |
| `<` | меньше | `NumberOfTestCasesFailed<1` |

Операторы приведены так, как их произносит автор; имена свойств произносятся только словами («number of test cases passed», «created by»), поэтому их точное написание — то, что показано в списке колонок окна поиска. В редакторе определения отчёта тот же запрос строится из полей **Link**, **Object type** и **Constraint**, что заодно показывает точное написание, которого ждёт Tosca.

### Пример: состояние ExecutionList

1. Начните с `SubParts` и типа объекта `ExecutionList`: результат перечислит все ExecutionList в workspace.
2. Таблица результатов предлагает свойства ExecutionList как поля фильтра, включая число прошедших и упавших TestCase.
3. Добавьте ограничение `NumberOfTestCasesPassed>1`, чтобы оставить только списки, где прошло больше одного TestCase.
4. Замените его на `NumberOfTestCasesFailed==0` (или `<1`), чтобы получить ExecutionList, в которых ничего не упало.

Тот же приём работает с любым объектом: требованиями, Module, TestStepValue, TestCase. Единственная сложность — структура подвыражений и имена свойств, которые совпадают с названиями столбцов в Commander.

## Виртуальные папки

Виртуальная папка не владеет объектами. Она хранит только TQL-запрос, а её содержимое — то, что запрос возвращает. Это сохранённый поиск: откройте папку вместо повторного ввода запроса.

### Создание

1. Перейдите в реальную папку, например `TestCases`. Виртуальную папку можно создать внутри любой папки любого раздела (TestCases, Modules, Requirements, Execution), но **не** прямо в корне проекта. По той же причине окно поиска отказывается сохранять в виртуальную папку, пока вы находитесь в корне.
2. Правой кнопкой по папке **> Create Virtual Folder**. Переименуйте её; при нескольких виртуальных папках понятное имя важно.
3. Откройте **Properties** папки и введите TQL-запрос. Пример из папки `TestCases`: `SubParts`, тип объекта `TestCase`, ограничение `CreatedBy=="Admin"`. Нажмите **OK** — папка заполнится всеми TestCase, созданными этим пользователем.

Расширяйте ограничение фильтром по дате создания, по workstate (завершён или нет), по признаку шаблона и т. д. Кто из пользователей сколько TestCase создал — готовый отчёт для руководства.

### Использование

- Результаты **не** обновляются сами. После изменений в workspace щёлкните правой кнопкой по папке **> Refresh Virtual Folder**, чтобы выполнить запрос заново.
- Запрос можно править в свойствах папки в любой момент.
- Виртуальная папка может быть источником отчёта; пункт есть в её контекстном меню (см. [Отчёты](/ToscaBase/ru/requirements-and-reporting/reports/)).

:::tip
Создайте несколько виртуальных папок для регулярно нужных представлений (упавшие ExecutionList, TestCase всё ещё `In Work`, требования без привязанных TestCase) и стройте анализ на них, а не на разовых поисках.
:::
