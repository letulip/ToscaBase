Tricentis Tosca — бесскриптовая платформа автоматизации тестирования на основе моделей (model-based testing) для сквозных (end-to-end) тестов. Вместо написания скриптов тестируемое приложение сканируется в **Module (модули)**, а **TestCase (тест-кейсы)** собираются из них перетаскиванием, поэтому функциональные, регрессионные и API-тесты строятся с минимальной подготовкой и короткой кривой обучения. Это коммерческий продукт Tricentis, позиционируемый как платформа непрерывного тестирования, которая быстро возвращает результаты в agile- и DevOps-конвейеры.

## Зачем автоматизация и почему Tosca

Автоматизированное тестирование заменяет ручные шаги теста шагами, которые выполняет инструмент. Цели — качество продукта, экономия человеческих усилий и более короткий цикл разработки. Инструменты предыдущего поколения (QTP/UFT, RFT, Selenium) требовали скриптов; преимущество Tosca в том, что та же работа делается без кода, поэтому тесты пишутся быстрее и большим числом людей, а стандартные отчёты для руководства формируются без доработок.

Tosca применяется для функционального и регрессионного тестирования, а тестирование API — часть того же инструмента, что важно в agile-проектах, где приложение тестируется слой за слоем, пока оно ещё строится.

## Тестирование на основе моделей

Определяющая особенность Tosca. Для каждой функциональности или экрана приложения тестировщик создаёт **Module**, в котором хранится техническая информация для управления им (контролы и их идентифицирующие свойства). TestCase строятся комбинированием Module. Поскольку технические детали живут в Module, а не в каждом тесте, изменение в приложении исправляется один раз — в Module. См. [Обзор Module](/ToscaBase/ru/modules/modules-overview/).

## Основные возможности

| Возможность | Что даёт |
|---|---|
| Бесскриптовая автоматизация | TestCase собираются перетаскиванием Module; параметризация тестовых данных и шаги проверки настраиваются, а не программируются |
| Тестирование на основе рисков | Требования имеют весовой коэффициент риска; Tosca выбирает подмножество набора тестов, минимизирующее риск, и измеряет покрытие рисков по результатам выполнения. См. [Требования и риски](/ToscaBase/ru/requirements-and-reporting/requirements-and-risk/) |
| Распределённое выполнение | Прогоны распределяются по нескольким машинам и запускаются по расписанию без участия человека. См. [Распределённое выполнение](/ToscaBase/ru/execution/distributed-execution-dex/) |
| Интеграция с CI/CD | Jenkins, Azure DevOps, Jira и подобные инструменты. См. [Интеграция с CI](/ToscaBase/ru/execution/ci-integration-jenkins/) |
| Динамические тестовые данные | TCD (test case design), TDM (test data management) и TDS (test data service); данные могут храниться в базе Tosca или во внешней |
| Запись | Тестовые сценарии записываются и превращаются в TestCase одним действием. См. [Recorder](/ToscaBase/ru/test-cases/recorder/) |
| Тестирование API | Компоненты, доступные через API, тестируются до появления UI. См. [Тестирование API](/ToscaBase/ru/api-testing/) |
| Виртуализация сервисов | Зависимые системы, недоступные во время выполнения, эмулируются, чтобы прогон мог продолжаться |
| Управление тестированием | Требования, отслеживание, анализ рисков, ручное и исследовательское тестирование, отчётность и аналитика в одном workspace |
| Нагрузочное тестирование | Упомянуто как поддерживаемое во вводном уроке QASCRIPT; в этой базе знаний не рассматривается |
| Сторонние инструменты | Perfecto, Selenium и qTest интегрируются с минимальной доработкой |

Поддерживаемые типы приложений: веб, desktop (.NET, PowerBuilder), SAP, Salesforce, мейнфреймы, мобильные устройства и API. Для идентификации элементов используется несколько технологий, которые продвигаются как основанные на ИИ.

## Tosca и Selenium

| | Tosca | Selenium |
|---|---|---|
| Стоимость | Лицензируемый, платный | Открытый, бесплатный |
| Подход | Без кода, на основе моделей | На основе скриптов, нужен язык программирования |
| Приложения | Веб, desktop, мобильные, API | Только веб |
| Поддержка | Команда поддержки вендора | Сообщество |
| Отчётность и репозиторий объектов | Встроены | В WebDriver отсутствуют |
| Тестирование API и нагрузочное | Включено | Из коробки нет |

Выбор зависит от бюджета, типов тестируемых приложений и навыков команды.

## Что нужно знать заранее

Обе серии уроков предполагают базовые знания тестирования ПО (тест-кейсы, шаги, проверки); программирование не требуется.
