Tosca 16.0 — выпуск с долгосрочной поддержкой, главная тема которого — автоматизация корпоративных приложений: новый **Tosca ID Mapper** и встроенная поддержка **ARIA** позволяют идентифицировать динамические контролы в Oracle и похожих ERP-системах без настройки каждого контрола. Также обновлён интерфейс Commander с тёмной и высококонтрастными темами, добавлен автоматизированный процесс **pre-execution approval (согласование перед выполнением)** для TestCase и ряд обновлений движков и платформы. Страница описывает то, что демонстрирует урок-источник; полный список — в блоге Tricentis «Introducing new features in Tosca 16».

Обновление — обычный запуск установщика: загрузите 16.0 с портала поддержки и пройдите мастер ([Установка](/ToscaBase/ru/getting-started/installation/)). **About Tosca** в Commander подтверждает версию.

## Улучшенная автоматизация Oracle: Tosca ID Mapper

Приложения Oracle, как и большинство ERP-систем, сильно кастомизированы, интегрированы со множеством других систем и полны динамических контролов, чьи ID меняются при каждой загрузке, поэтому идентификация по ID ненадёжна. ID Mapper позволяет один раз на приложение задать стратегию **ID по умолчанию (default ID)**, которую затем использует каждый контрол этого приложения.

В демонстрации сканируется страница «создать контакт» Oracle ERP с текстовыми полями, выпадающими списками и кнопками, у которых все ID динамические.

1. В **Modules** создайте папку, отсканируйте приложение и перейдите на вкладку **Advanced** в XScan.
2. Нажмите новый **значок настроек** в окне XScan и откройте **Unique application identifiers**.
3. Определите приложение: имя (например, `Oracle`), **идентификатор приложения** (`Title` по умолчанию; второй вариант — `URL`) и его значение, которое подставляется с текущей страницы. Сохраните.
4. Выберите контрол, например текстовое поле *First name*. Он идентифицирован по `id` и тегу, но id динамический. Снимите флажок с id и отметьте стабильные свойства: **name** по умолчанию (`first name`) и **visible** (`true`).
5. В настройках контрола выберите **Define default ID at application level** — откроется **Select application**; выберите приложение из шага 3 и сохраните. Контрол перезагрузится с ID по умолчанию.

С этого момента каждый другой контрол этого приложения (например, поле *Last name*) автоматически идентифицируется по тем же свойствам по умолчанию, а не по id и тегу. Время на настройку падает, стабильность растёт, а сохранённую библиотеку идентификаторов могут переиспользовать другие. Общие правила уникальной идентификации — в [Идентификации контролов](/ToscaBase/ru/modules/control-identification/).

## Поддержка фреймворка ARIA

**ARIA** (Accessible Rich Internet Applications) — фреймворк, делающий веб-контент доступным для экранных дикторов, экранных луп и синтеза речи. Его используют Oracle, Workday, Microsoft Dynamics 365, SAP и другие, а распространение подталкивает регулирование доступности в ЕС, которое, по словам источника, станет обязательным для большинства приложений к 2025 году. Tosca 16.0 умеет идентифицировать контролы по их ARIA-меткам нативно; параметр управления (steering parameter) определяет, учитывается ли встроенная поддержка ARIA.

В демонстрации сканируется страница «добавить отсутствие», где три кнопки **Save and close**, **Submit** и **Cancel** находятся внутри таблицы.

- В XScan **значок настроек > General settings** есть флажок **ignore ARIA controls**. По умолчанию он снят, то есть ARIA-контролы учитываются; отметьте его, чтобы всё идентифицировалось обычными свойствами.
- Без поддержки ARIA эти три кнопки видны как элементы `div`, которые трудно идентифицировать из-за отсутствия уникальных свойств. С ней они видны как **кнопки**, а свойство adapter контрола читается как `Tricentis.Automation.Engines.Adapter.Aria.AriaButtonAdapter` (как произнесено в источнике).
- Выберите кнопки, сохраните Module и управляйте ими как любыми другими кнопками.

Оставляйте поддержку ARIA включённой везде, где приложение использует ARIA-контролы.

## Новый интерфейс и темы

В Tosca 16 изменены значки папок и цвета по всему Commander. Переключатель тем в верхней части окна предлагает **Light** (по умолчанию), **High contrast light**, **High contrast dark** и **Dark**. Тёмная тема подойдёт тем, кто привык к тёмным IDE; настройку можно вернуть в любой момент.

## Pre-execution approval для TestCase

Автоматизированный процесс запроса и выдачи согласования TestCase перед выполнением, чтобы запускались только проверенные TestCase и никакое несанкционированное изменение не проникло после проверки. Он охватывает **только TestCase** — не шаблоны TestCase, бизнес-TestCase, Module или ExecutionList.

Процесс переиспользует **Workstate** TestCase, который Tosca теперь выставляет сама:

| Событие | Workstate |
|---|---|
| Новый TestCase в работе | `Planned` |
| Пользователь запросил согласование | `In Work` |
| Согласован | `Completed` |
| Отклонён | обратно в `Planned` |

Функция работает только в **многопользовательском workspace**, потому что проверку и согласование выполняет назначенная группа пользователей. Включается правым щелчком по корню проекта и выбором пункта в меню; группы пользователей для согласования создаются на том же уровне. В источнике показать её не удалось из-за однопользовательского workspace.

Сравните с ручным [процессом ревью](/ToscaBase/ru/best-practices/review-process/) на основе папок, который pre-execution approval автоматизирует, и с [Пользователями и группами](/ToscaBase/ru/administration/users-and-groups/).

- Поддержка приложений на Java 17
- Поддержка Windows 11
