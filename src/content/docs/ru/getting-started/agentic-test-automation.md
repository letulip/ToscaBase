**Tosca Agentic Test Automation (агентная автоматизация тестов)** — возможность **Tricentis Tosca Cloud**, браузерной редакции Tosca, доступной по адресу `https://<организация>.my.tricentis.com`. ИИ-агент читает шаги теста, написанные на простом английском, управляет приложением, создаёт **Module** для каждого затронутого контрола, собирает **TestCase** с TestStep, значениями и проверками, сохраняет и запускает его. Всё остальное в этой базе знаний строится в настольном Tosca Commander; объекты те же (Module, TestCase, TestStep, TestStepValue), меняется лишь способ их получения. Страница следует уроку-источнику, записанному на 14-дневном trial.

## Традиционный и агентный подход

| Без агента (Commander или Tosca Cloud) | С Tosca Agentic Test Automation |
|---|---|
| 1. Отсканировать контролы приложения в Module и сохранить их | Записать тест нумерованными шагами на простом английском |
| 2. Создать TestCase | Шаги 1–6 выполняет агент |
| 3. Добавить TestStep, сопоставленные с Module | |
| 4. Ввести TestStepValue для каждого шага | |
| 5. Запустить TestCase и отладить | |
| 6. Прочитать результаты | |

Сначала урок показывает левую колонку в Tosca Cloud (**Build > All assets**, **Module scan**, открывающий XScan через launcher, **New test case**, добавление отсканированных Module из **User assets**, ручной ввод данных автомобиля), чтобы было видно, сколько ручных действий убирает агент.

## Получение доступа

1. Запросите **14-дневный бесплатный trial** Tosca Agentic Test Automation на сайте Tricentis: корпоративный email, имя и фамилия, страна, телефон, должность, согласие на маркетинговые рассылки, затем **Request trial**.
2. Приходит письмо; ссылка из него открывает Tricentis Tosca Cloud и запрашивает **имя организации**. Оно становится вашим URL — `https://<организация>.my.tricentis.com`.
3. При первом щелчке по значку **Tosca Agentic Test Automation** введите имя организации, затем имя пользователя и пароль, созданные при регистрации.

Облачный workspace открывается с кратким руководством по началу работы.

## Предпосылки

Агент работает в облаке, а тестируемое приложение — на вашей машине, поэтому нужны локальные компоненты:

- Машина с **Windows**.
- **Launcher** — небольшое приложение, загружаемое из Tosca Cloud; оно устанавливает всё нужное для управления локальными приложениями и открывает XScan для ручного сканирования.
- **Tricentis automation extension для Chrome** — обязательно для любого веб-приложения (о настольном аналоге см. [Tosca Automation Extension](/ToscaBase/ru/getting-started/tosca-automation-extension/)).
- **Локальный агент**, зарегистрированный в разделе **Agents** Tosca Cloud (в уроке — персональный агент на ноутбуке ведущего). Через него выполняются прогоны, запущенные из облака.
- Приложение, открытое в окне браузера до начала работы; в уроке это демо-приложение Tricentis **vehicle insurance** в Edge.

## Генерация TestCase из простого английского

1. Подготовьте шаги. В уроке они хранятся в текстовом файле: URL приложения; нажать **Get a quote**; выбрать марку `Audi`; ввести мощность двигателя, дату выпуска, число мест, тип топлива `Diesel`, грузоподъёмность, полную массу, прайсовую цену, номерной знак и годовой пробег; нажать **Next**; проверить, что поле *First name* видимо; проверить, что поле *Last name* видимо. Всего пятнадцать строк.
2. На главной странице Tosca Cloud нажмите **Tosca Agentic Test Automation**, затем **Generate a test case**.
3. Выберите технологию Module: **TBox** или **Vision AI**. До недавнего времени агент создавал только Vision AI Module; теперь он создаёт и TBox Module, которые предпочтительнее для сопровождения. В уроке выбран TBox.
4. **Continue** и **Open launcher**. Launcher инициализирует *TBox inspection agent* (или агент Vision AI) и перечисляет открытые окна приложений; выберите окно с приложением. Слева появляется окно промпта агента, справа — приложение.
5. Введите шаги прямо в чат или **прикрепите** файл с промптом. Выберите режим:
   - **Co-create** — агент запрашивает одобрение и задаёт вопросы на каждом шаге.
   - **Autonomous** — агент проходит шаги самостоятельно.
6. Введите цель одной строкой (в уроке — *Get a quote for insurance*) и нажмите Enter. Агент читает файл строка за строкой, открывает URL, щёлкает, заполняет поля, создаёт Module для контролов каждой страницы и выполняет проверки видимости. По завершении уведомление просит вернуться в окно автоматизации.
7. Нажмите **Save test case**. Если в workspace уже есть Module, их можно переиспользовать; иначе выберите **Keep new modules**. TestCase и его Module отправляются в Tosca Cloud, показывается ссылка на новый TestCase.

В **Build > All assets** теперь лежат сгенерированные Module (два — по одному на страницу) и TestCase `Get insurance quote vehicle data` с его TestStep. Свойства Module — свойства TBox, а не Vision AI.

## Запуск

Откройте TestCase, задайте параметр `Browser` (в уроке — `Edge`; новые параметры добавляются там же) и нажмите **Run**. Локальный агент воспроизводит шаги в браузере. **View last run** показывает каждый TestStep со статусом *Passed*.

## Ограничения, названные в источнике

- Trial длится 14 дней и требует корпоративный email.
- Launcher, расширение Chrome и локальный агент должны быть установлены и зарегистрированы; без launcher агент не может открыть приложение.
- Показанный сценарий — один поток из 15 шагов с двумя проверками видимости; более сложные сквозные случаи ведущий откладывает на следующий урок.
- Поддержка TBox в агенте появилась недавно; раньше генерировались только Vision AI Module.

:::note
Урок не показывает, как редактировать сгенерированный TestCase, как агент обращается с контролами, которые не может идентифицировать, и как облачный workspace связан с workspace настольного Commander. Считайте это открытыми вопросами, а не недостатками продукта.
:::
