Проверить PDF в Tosca можно двумя способами. Стандартный Module `1:1 Compare` из набора TBox сравнивает документ целиком с эталоном с заданной точностью, без создания собственных Module (модулей). **PDF Scan** из PDF engine (движка PDF) строит Module из выделенных областей документа (текст, картинка, таблица), чтобы проверять отдельные значения в TestCase (тест-кейсе). Типичный сквозной сценарий: прогнать веб-приложение, дождаться сформированного PDF и проверить его одним из этих способов.

## Быстрое сравнение: `1:1 Compare`

Стандартный Module TBox `1:1 Compare` находится рядом с другими Module сравнения (сравнение файлов, картинок, Excel). Добавьте его в TestCase и заполните атрибуты:

| Атрибут | Значение |
|---|---|
| Reference PDF | Полный путь к эталонному документу, включая расширение `.pdf` |
| Reference password | Пароль эталона, если он защищён; Tosca введёт его сама |
| Target PDF | Полный путь к документу, который сравнивается с эталоном |
| Target password | Пароль целевого документа, если есть |
| Accuracy | Требуемое совпадение в процентах. `100` означает полную идентичность; меньшее значение допускает небольшие расхождения |
| Excluded pages | Страницы, исключённые из сравнения. Несколько записей разделяются точкой с запятой; допускается и диапазон страниц |

Как оценивается результат:

- При точности `80` два слегка различающихся одностраничных документа **проходят**. В log info сказано, что условие успеха выполнено: каждая страница целевого документа и эталона совпала не менее чем на 80 процентов, исключённых страниц нет.
- При точности `100` тот же TestCase **падает**. В log info перечислены области, где найдено хотя бы одно различие (верх слева, верх справа, середина слева, середина справа, низ справа и т.д.).

:::note
Сравнение сообщает только *где* на странице есть различие, но не *какое*. Это быстрая общая проверка. Для проверки конкретных значений нужен PDF Scan (ниже).
:::

:::note
В примере автора исключаются страница 1, диапазон страниц с 3 по 4 и страница 5, разделённые точкой с запятой. Символ внутри диапазона в видео не произнесён; сверьтесь с подсказкой к атрибуту в своей версии Tosca.
:::

## Сканирование PDF через PDF Scan

1. В разделе **Modules** щёлкните папку правой кнопкой и выберите **Scan > PDF** (не **Application**: тот вариант для десктопных и веб-приложений).
2. Выберите PDF-документ. Откроется окно **PDF Scan** с предпросмотром всех страниц.

На панели инструментов:

- **Zoom fit**, увеличение и уменьшение.
- **Select document language**.
- **Show content preview**: панель, показывающая значение только что отсканированного элемента. По умолчанию может быть скрыта.
- **Scan new document** для перехода к другому PDF, **Save** для сохранения отсканированных контролов и **Close**.
- Три инструмента сканирования, по одному на тип элемента в PDF: **Text**, **Image** и **Table**.

### Текстовые и графические контролы

1. Нажмите **Text** (или **Image**); курсор превратится в плюс.
2. Обведите область прямоугольником. Tosca распознает её содержимое и покажет его в content preview. Если возможны более длинные значения, рисуйте прямоугольник с запасом.
3. Справа появится контрол с типом и общим именем. Двойной щелчок переименовывает его (например `Make`, `FuelType`, `Logo`).
4. **Jump to** подсвечивает отсканированную область на странице, **Redraw** позволяет изменить область, **Remove** удаляет контрол.

### Табличные контролы

Табличный контрол работает хорошо только для настоящей таблицы с выровненными строками и столбцами; иначе Tosca не отличит строки от столбцов. Настройки отсканированной таблицы:

- **Use header row** / **Use header column** и какая строка является заголовком (по умолчанию первая).
- Подгонка границ ячеек, если автоматическая сетка легла неточно; при наведении показываются координаты.
- **Consider invisible cells**.

### Сохранение Module

Нажмите **Save** и закройте PDF Scan. Новый Module назван по пути к файлу; переименуйте его (например `InsuranceQuotePDF`). Он содержит отсканированные контролы и два ModuleAttribute (атрибута модуля): `Target PDF` (путь к проверяемому документу) и `PDF password`.

## Проверка элементов PDF в TestCase

1. Создайте TestCase и добавьте отсканированный Module как TestStep (шаг теста).
2. Укажите в `Target PDF` путь к документу с расширением `.pdf`. `PDF password` оставьте пустым, если он не нужен.
3. **Текстовый контрол**: введите ожидаемое значение. ActionMode (режим действия) автоматически становится `Verify`, поскольку с PDF обычно делают именно проверку.
4. **Графический контрол**: проверьте свойство `Exists` со значением `True`.
5. **Табличный контрол**: Module содержит строки и ячейки. Выберите столбец по номеру, затем ячейку по номеру и введите ожидаемое значение. Подстановочные знаки помогают, когда в ячейке кроме нужного значения есть другой текст: `*Bonus 1*` проходит, даже если до или после есть что-то ещё.

После выполнения в log info видна каждая проверка: ожидаемое и фактическое значение текста совпали, картинка существует, ячейка таблицы соответствует шаблону. Используйте `*` везде, где часть текста постоянна, а остальное меняется.

## Подсчёт страниц PDF

В некоторых PDF нет номера страницы в колонтитулах, и общее количество прочитать неоткуда. Обходной путь использует то, что Module PDF обходит все страницы, если контролу разрешено находиться на любой странице.

1. **Scan > PDF**, откройте документ и создайте один контрол **Text** в любом месте любой страницы; где именно, не важно. Сохраните и переименуйте Module (например `SamplePDF`).
2. Под контролом текстовой области в Module есть элемент уровня документа, который автор называет «div element». Если он не отображается, выделите Module и нажмите **F12**.
3. Откройте свойства этого элемента. Свойство `Page` равно `1`; замените на `*` (любая страница). Закройте свойства.
4. Создайте TestCase, добавьте Module и укажите `Target PDF`.
5. Для элемента уровня документа выберите ActionMode `Buffer` с именем буфера, например `PageCount`.
6. Для текстового контрола (`PDF Area 1`) проверьте значение `*`: оно совпадает с любым текстом на любой странице.
7. Установите workstate «completed» и запустите в ScratchBook. Для длинных документов выполнение займёт больше времени, так как Tosca проходит каждую страницу.

В логе видно, как буфер получает значения 1, 2, 3 ... и в конце номер последней страницы (в видео 57); проверка успешна, потому что `*` всегда истинно. Итоговое значение смотрите в **Tools > Buffer Viewer** или проверьте его в следующем TestStep.

:::note
«Div element» — это название автора; подпись элемента в дереве Module на экране не видна, поэтому ищите элемент со свойством `Page`.
:::

Если в колонтитуле PDF есть номера страниц, отсканируйте эту область как текстовый контрол, пометьте её в PDF Scan как повторяющуюся область (repetitive area) и буферизуйте значение при обходе; последнее буферизованное значение и есть количество страниц.
