Помимо отправки и сканирования, в API Scan есть секция **Message** с инструментами проверки и приведения в порядок payload; SOAP-сервисы с XML-телами он обрабатывает так же, как REST; и он умеет прикреплять файлы к запросу. Документ покрывает эти три возможности. Само сканирование — в [Основах API Scan](/ToscaBase/ru/api-testing/api-scan-basics/); построение TestCase из сообщений — в [TestCase для API](/ToscaBase/ru/api-testing/api-test-cases/).

## Инструменты payload в секции Message

Четыре опции действуют на payload выделенного сообщения. Они особенно полезны при работе со свежеразработанными API или написанными вручную сообщениями, до начала тестирования.

### Validate

Проверяет структурную корректность сообщения и его payload, например что JSON-тело правильно сформировано. Для корректного сообщения строка состояния сообщает **No error found**. Удалите закрывающую фигурную скобку — и **Validate** перечислит ошибки, например что JSON-токен недопустим для закрытия объекта, с указанием **строки и позиции**. Исправьте payload и проверьте снова. Сообщение, не прошедшее валидацию, не получит ответа от сервера, так что это первое, что стоит проверить, когда запрос ведёт себя странно.

### Pretty Print

Восстанавливает переносы строк и отступы payload согласно его формату (JSON или XML). Полезно после вставки или ручного редактирования тела.

### Word Wrap

Переносит очень длинные строки, чтобы весь payload помещался в панель. В источнике вставляется целое JSON-определение Petstore, которое приходит одной-двумя огромными строками; **Word Wrap** разбивает его на читаемые строки, а **Pretty Print** затем восстанавливает структуру JSON. Вместе они делают большой исходный файл пригодным для поиска.

### Search in payload

Открывает диалог поиска по payload: **Find next** подсвечивает следующее совпадение. Опции: **match case**, **match whole word**, **regular expression**, **wildcards** и **search up** для поиска вверх. Кнопки **Replace** и **Replace all** меняют текст на месте; диалог сообщает, когда совпадений больше нет. В примере питомца переименовывают из `range` в `range1`.

## SOAP-сервисы

SOAP API используют XML вместо JSON и для запроса, и для ответа, а запросы — `POST`. Сканирование идентично REST: выберите **URI** (или **File**), укажите адрес WSDL, нажмите **OK**. В демо сканируется пример сервиса Tricentis `calculator.svc`; результат — папка `Calculator` с сообщением на каждую операцию: `Add`, `Divide`, `Multiply`, `Subtract`. Откройте `Add`, поставьте `10` в каждый узел-операнд XML-тела, запустите — ответ со статусом `200` и XML-payload, где результат `20`.

Единственное отличие от REST — формат payload, поэтому проверки строятся по XML-узлам, а не по JSON-полям. Всё остальное (экспорт, Module, TestCase, верификации) то же самое.

### Верификация SOAP-вычисления через Configuration Parameters

Источник экспортирует сообщение `Add` из standalone API Scan как subset, импортирует его в папку компонента `SOAP API testing` (механизм описан в [TestCase для API](/ToscaBase/ru/api-testing/api-test-cases/)), затем:

1. В Module запроса добавьте оба узла-операнда как ModuleAttribute; в Module ответа — **код состояния** и узел **result**.
2. В TestCase верифицируйте код состояния как `200`.
3. Создайте два Test Configuration Parameter, `num1` и `num2`, со значениями (см. [Test Configuration Parameters](/ToscaBase/ru/data-and-parameters/test-configuration-parameters/)) и задайте операнды запроса как `{CP[num1]}` и `{CP[num2]}` вместо статических чисел.
4. Верифицируйте результат математическим выражением над теми же параметрами: `{MATH[{CP[num1]}+{CP[num2]}]}` (о выражении `MATH` см. [Случайные значения](/ToscaBase/ru/expressions/random-values/)). Считайте скобки: пропущенная скобка — ошибка, которую источник допускает с первой попытки.
5. Запустите в ScratchBook. Лог показывает обе верификации с равными ожидаемым и фактическим значениями.

Так входные данные меняются в одном месте, а ожидаемый результат вычисляется, а не зашивается в тест.

## Отправка вложений

Некоторые запросы несут файл: изображение, документ, JSON-исходник. Чтобы прикрепить его:

1. Создайте сообщение (`test attachment` в источнике), задайте метод `POST` и endpoint сервиса, принимающего загрузки. В демо используется Postman Echo, который возвращает полученное содержимое.
2. Под payload откройте вкладку **Attachments**. У каждого вложения есть **Name**, **File** и **Content type**.
3. Щёлкните поле **File**; появится кнопка **Load** с многоточием. Нажмите её и выберите файл.
4. Тип содержимого **определяется автоматически**, имя заполняется из имени файла; оба можно изменить.
5. Запустите. Ответ — статус `200`, а Postman Echo возвращает содержимое файла в payload в закодированном виде, так что человеку оно нечитаемо.

Дополнительные опции на вкладке: **Content transfer encoding**, **Content type**, **Omit file name** и **Enable MTOM**.

:::note
Автор не знает, что делает **Enable MTOM**, и не объясняет остальные три опции. MTOM — механизм SOAP для эффективной передачи двоичных вложений; специфичных для Tosca деталей источник не даёт, поэтому оставляйте опции по умолчанию, если документация API не требует иного.
:::
