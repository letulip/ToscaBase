Сканирование определения (см. [Основы API Scan](/ToscaBase/ru/api-testing/api-scan-basics/)) работает только когда вам дали Swagger, WSDL или подобный файл. Когда API-вызовы приложения не задокументированы, **Message Recorder (рекордер сообщений)** в API Scan записывает трафик между тестируемой системой и её бэкендом, показывает каждый вызов как API-сообщение и экспортирует выбранные, чтобы из них можно было строить TestCase.

## Открытие рекордера

Нажмите **Record** в верхней панели API Scan. В окне Message Recorder есть:

| Элемент | Назначение |
|---|---|
| **Start** / **Stop** | Начать и завершить сеанс записи (трассировку сообщений). После запуска кнопка превращается в Stop |
| **Clear all** | Удалить все захваченные сообщения |
| **Configure** | Адрес, имя пользователя и пароль прокси; опция **расшифровки HTTPS-трафика** |
| **Export** | Передать выделенные сообщения в API Scan как сообщения |

## Запись сеанса

1. Нажмите **Start**. Список остаётся пустым, пока нет трафика.
2. Создайте трафик. Либо запустите TestCase из Tosca Commander (в источнике в ScratchBook выполняется веб-TestCase Vehicle Insurance), либо поработайте с приложением в браузере сами; рекордеру всё равно, он захватывает всё, что отправляет тестируемая система.
3. Наблюдайте, как заполняется список. У каждой записи видны **result** (код состояния), **host URL**, **content type** и **process**. Щёлкните запись, чтобы увидеть полные детали запроса и ответа в панелях.
4. По окончании нажмите **Stop**.

В демо целый UI TestCase порождает один-единственный HTTP-запрос, потому что пример приложения почти целиком фронтенд. Ручной вызов действия на бэкенде — генерация документа со страницы — добавляет второе сообщение с типом содержимого `application/pdf` и результатом `200`. В этом и смысл рекордера: он показывает, какие взаимодействия действительно доходят до бэкенда и что они отправляют.

## Экспорт захваченных сообщений

1. **Выделите все сообщения**, которые нужны. Экспортируются только выделенные; в источнике первый экспорт с одним выделенным даёт одно сообщение.
2. Нажмите **Export**.

API Scan создаёт папку `Trace_import` с папкой на каждое сообщение, где лежит сообщение с endpoint, resource и payload ровно в записанном виде. Дальше рабочий процесс обычный: подправьте сообщения, запустите их и экспортируйте в Commander, как описано в [TestCase для API](/ToscaBase/ru/api-testing/api-test-cases/).

Очистка списка и повторное нажатие **Start** начинают новый сеанс.

## Когда применять

- Разработчики не предоставили документацию API, но вы знаете, что приложение общается с API.
- Вы хотите увидеть, какие вызовы бэкенда запускает UI-сценарий, прежде чем решать, что тестировать на уровне API.
- Новый API в разработке, и вы хотите захватить реальные вызовы, чтобы начать верификацию пораньше.

:::tip
Запустите рекордер во время выполнения существующего UI TestCase: вы получите точные запросы, стоящие за уже автоматизированным сценарием, готовые превратиться в быстрые проверки на уровне API.
:::
