Три вопроса, которые постоянно возникают в реальных проектах и не имеют очевидного модуля: перемещение между вкладками браузера, подсчёт всех ссылок (кнопок, чекбоксов) на странице и скачивание файла для последующей проверки. Общая нить — правило запасного варианта: если у Tosca нет прямого метода, эмулируйте то, что пользователь сделал бы с клавиатуры, обобщите один атрибут Module (модуля) так, чтобы он подходил многим контролам, или запустите внешний инструмент командной строки. Документы по Obstacle Course ([идентификация](/ToscaBase/ru/troubleshooting/obstacles-identification/), [таблицы](/ToscaBase/ru/troubleshooting/obstacles-tables/), [ввод и клики](/ToscaBase/ru/troubleshooting/obstacles-input-and-clicks/)) покрывают головоломки уровня страницы; этот документ — уровня окружения.

## Переключение вкладок браузера

**Проблема.** Приложение открывает несколько вкладок, и TestCase (тест-кейс) должен перейти на третью, потом на пятую, потом обратно.

**Причина.** В Tosca нет модуля, переключающего вкладки браузера.

**Решение.** Отправьте сочетания клавиш, которые нажал бы пользователь, стандартным модулем `TBox Send Keys`:

1. Добавьте `TBox Send Keys` как TestStep (шаг). Его `Caption` — заголовок окна браузера; используйте характерную часть заголовка с подстановочным знаком, чтобы он совпадал и после смены заголовка страницы.
2. В `Keys` запишите сочетание кодами SendKeys:

| Цель | Сочетание | Значение Keys |
|---|---|---|
| Перейти на вкладку 3 | Ctrl+3 | `^3` |
| Следующая вкладка | Ctrl+Tab | `^{TAB}` |
| Предыдущая вкладка | Ctrl+Shift+Tab | `^+{TAB}` |

Коды — те же, что у класса `SendKeys` в Microsoft .NET: `^` — Ctrl, `+` — Shift, `%` — Alt, именованные клавиши в фигурных скобках (`{TAB}`). Полный список — в документации класса `SendKeys`; все коды оттуда работают в Tosca.

Нумерованную форму используйте, когда знаете нужную вкладку; `^{TAB}` / `^+{TAB}` — когда число вкладок неизвестно.

:::tip
Та же идея работает для любого отсутствующего метода: если пользователь может сделать это с клавиатуры, `TBox Send Keys` тоже может.
:::

## Подсчёт всех ссылок (или любого набора похожих контролов)

**Проблема.** Проверить, что на странице товаров показано шесть продуктов. Названия продуктов — ссылки; на странице их может быть сотня, так что сканировать каждую — не вариант.

**Причина.** По умолчанию атрибут Module соответствует ровно одному контролу и используется один раз.

**Решение.** Сделайте так, чтобы один атрибут соответствовал всем, и посчитайте совпадения. Пример со страницы товаров SauceDemo:

1. Отсканируйте одну ссылку продукта. Её `tag` — `a`; `id` — `item_4_title_link`. У другого продукта `item_0_title_link`: префикс меняется, суффикс `title_link` постоянен.
2. В Module переименуйте атрибут во что-то общее (`Product`). В свойстве `id` замените меняющуюся часть подстановочным знаком, оставив `*title_link`. Теперь атрибут соответствует каждой ссылке продукта.
3. Установите **cardinality** (кардинальность) `0-n` и добавьте Configuration Parameter `ExplicitName = True`, чтобы атрибут можно было использовать многократно и переименовывать в TestStep, если нужно ещё и кликать по отдельным ссылкам.
4. TestCase *Get product count*: `Product` → свойство `ResultCount`, ActionMode `Buffer`, значение `b_products`. `ResultCount` возвращает число подошедших контролов.
5. Добавьте `TBox Evaluation Tool` с выражением `{B[b_products]}==6`. Он проходит, когда выражение истинно; лог ScratchBook показывает, что `b_products` установлен в `6` и `6==6` вычислено как `True`.

Уберите свойство `id` совсем — и атрибут будет соответствовать **каждой** ссылке на странице (все теги `a`). Тот же рецепт считает кнопки или отмечает все чекбоксы на странице — через обобщение общего свойства. См. [Evaluation Tool](/ToscaBase/ru/standard-modules/evaluation-tool/) и [Buffers](/ToscaBase/ru/data-and-parameters/buffers/).

## Скачивание и проверка файла

**Проблема.** Скачать файл (PDF, изображение, медиа) из приложения и затем проверить его, например [PDF-движком](/ToscaBase/ru/engines/pdf-engine/).

**Причина.** Клик по ссылке скачивания сохраняет файл в папку *Downloads* браузера; затем его нужно перенести или направить последующие шаги на эту папку. Работает, но цепочка длинная и порой хрупкая.

**Решение.** Скачивайте напрямую через `curl` из TestStep.

`curl` (client for URL) — бесплатный open-source инструмент командной строки для передачи данных по сетевым протоколам. Установите его на Windows и проверьте командой `curl --help` в командной строке; если появился список опций, инструмент доступен. Базовая форма скачивания:

```text
curl <url файла> -o <целевой путь\имя файла>
```

В Tosca:

1. Добавьте стандартный модуль `TBox Start Program`. Укажите программу `powershell.exe`.
2. Передайте аргументы по порядку: `curl`, URL файла, `-o` и полный целевой путь (например, `C:\Temp\media.png`).
3. Установите `Wait for exit` в `True`, чтобы TestCase дождался завершения скачивания.
4. Добавьте `TBox File Existence` с целевой папкой и именем файла, ActionMode `Verify`. Лог сообщает об одном совпадении, когда файл на месте.

Дальше файл можно передать любому движку или файловому модулю; см. [Операции с файлами и папками](/ToscaBase/ru/standard-modules/file-and-folder-operations/) и [Запуск и закрытие программ](/ToscaBase/ru/standard-modules/start-and-close-programs/).
