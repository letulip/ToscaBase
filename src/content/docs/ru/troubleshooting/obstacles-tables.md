Веб-таблицы — место, где живёт большинство реальных проблем управления: строки меняют позицию между загрузками страницы, число строк неизвестно, то, что выглядит как таблица, — набор `div`, или нужный контрол находится внутри ячейки, а XScan поместил его вне строки. Препятствия ниже решаются небольшим набором инструментов: ActionMode `Constraint` (ограничение) для выбора строки, ActionMode `Buffer` для чтения ячейки, свойства таблицы `RowCount`, `ColumnCount` и `ResultCount`, селекторы строк вроде `$last`, динамический буфер `{XB[...]}` и встроенные контролы внутри строки. Базовые понятия — в [Табличных контролах](/ToscaBase/ru/modules/table-controls/) и [ActionModes](/ToscaBase/ru/test-cases/action-modes/).

У каждого препятствия одинаковая рутина: отсканировать Module в папку *Obstacles*, создать TestCase с именем препятствия, перетащить в него Module, поставить workstate *Completed*, запустить в ScratchBook.

## Не таблица (препятствие 3)

**Проблема.** Клик по *Generate order ID* добавляет номер заказа в то, что похоже на таблицу, в случайную строку. Номер нужно забуферизовать и ввести в текстовое поле, причём TestStep должен работать при каждом запуске.

**Причина.** XScan не показывает ни строк, ни ячеек: «таблица» — вложенные `div`. У `div` с номером заказа динамический `InnerText` и никаких других отличительных свойств; стоит снять `InnerText`, и элемент не уникален, потому что всё вокруг — `div`.

**Решение.**

1. Поднимайте уровень **filtered items**, пока не появится `div` с номером заказа.
2. Снимите `InnerText` (он меняется каждый раз). Переключите метод идентификации с *Identify by properties* на *Identify by anchor* (по якорю).
3. Перетащите `div` со статической подписью *Order ID* в слот anchor control. Где бы ни оказалась строка, подпись всегда рядом с номером, поэтому элемент становится уникальным.
4. Снова понизьте уровень фильтра и добавьте ссылку *Generate order ID* и текстовое поле. Переименуйте атрибут номера в `Order ID`.
5. TestCase, в таком порядке: ссылка → `X`; `Order ID` → свойство `InnerText`, ActionMode `Buffer`, значение `orderId`; текстовое поле → `{B[orderId]}`.

Идентификация по якорю описана в [Идентификации контролов](/ToscaBase/ru/modules/control-identification/).

## Сложные взаимодействия с таблицей (препятствие 5)

**Проблема.** Нажать кнопку *Edit* в строке *John Doe*. Каждое обновление перемешивает строки, и есть две строки с именем *John*.

**Причина.** Индекс строки ничего не значит, а XScan помещает отсканированную кнопку *Edit* рядом с таблицей, а не внутрь строки.

**Решение.**

1. Отсканируйте таблицу и одну кнопку *Edit* (на *not unique* не обращайте внимания) и сделайте кнопку встроенным контролом строки, как описано в разделе [Встроенные контролы внутри таблицы](/ToscaBase/ru/modules/table-controls/#встроенные-контролы-внутри-таблицы).
2. TestCase: в строке ячейка *First name* = `John` и ячейка *Last name* = `Doe`, обе с ActionMode `Constraint` (одного Constraint мало, потому что *John* встречается дважды); *Edit* → `X`.

Два Constraint отфильтровывают ровно одну строку независимо от её позиции; клик применяется к кнопке этой строки.

## Много строк (препятствие 18)

**Проблема.** Посчитать строки таблицы, ввести число в *Row count*, нажать кнопку. После каждого клика размер таблицы меняется, так что статическое число не подходит.

**Причина.** Число строк известно только во время выполнения.

**Решение.** У табличного контрола Tosca есть свойства `RowCount` и `ColumnCount`.

1. Module: таблица, текстовое поле, кнопка.
2. Таблица → свойство `RowCount`, ActionMode `Buffer`, значение `rows`.
3. Текстовое поле → `{B[rows]}`; кнопка → `X`.

Работает одинаково для статических и динамических таблиц.

## Последняя строка (препятствие 19)

**Проблема.** Проверить, что в последней строке есть значение заказа, и скопировать его в текстовое поле. Ни значение, ни число строк не постоянны.

**Причина.** Индекс «последней строки» меняется.

**Решение.** В TestStep откройте атрибут строки таблицы и используйте селектор вместо номера:

- `$last` выбирает последнюю строку.
- `$lastContentRow` делает в этом препятствии то же самое; оба варианта есть в выпадающем списке строки.

Затем в ячейке столбца *Value* поставьте ActionMode `Buffer` со значением `b_val` и введите `{B[b_val]}` в текстовое поле.

В списке селекторов также есть `$1` для первой строки, `$n` для любого номера, строка заголовка и первая пустая строка. С ними можно верифицировать или буферизовать любую строку, не привязываясь к её позиции.

## Поиск по таблице (препятствие 21)

**Проблема.** Динамическая таблица; узнать, содержит ли какая-либо ячейка значение `15`, и ввести `true` или `false` в текстовое поле.

**Причина.** Значение может оказаться в любой строке и любом столбце — или отсутствовать.

**Решение.**

1. Module: таблица и текстовое поле.
2. TestCase: в строке задайте ячейке `15` с ActionMode `Constraint`. Tosca отфильтрует строки до той, где эта ячейка есть, в любом столбце.
3. На строке используйте свойство `Exists` с ActionMode `Buffer` и значением `b_exists`. Буфер получит `True`, если строка, найденная по Constraint, существует, и `False` иначе.
4. Текстовое поле → `{B[b_exists]}`.

Constraint плюс `Exists` — самый быстрый способ найти значение во всей таблице.

## Планировщик встреч (препятствие 22)

**Проблема.** Расписание: время в заголовках строк, дни недели в заголовках столбцов. Прочитать статус (*open* / *closed*) для четверга, 11–13, и ввести его в текстовое поле.

**Причина.** Ничего сложного, кроме умения адресовать ячейку по заголовкам; строка и столбец заданы.

**Решение.**

1. Module: расписание и поле результата.
2. TestCase: в атрибуте строки введите текст заголовка строки (`11 - 13`, как на странице). Tosca выберет строку по этому тексту при условии, что он уникален.
3. Ячейка: выберите столбец `Thursday` из заголовков столбцов, ActionMode `Buffer`, значение `b_status`.
4. Текстовое поле → `{SENDKEYS "{B[b_status]}"}`.

:::note
Если бы время было динамическим, его пришлось бы сначала буферизовать или наложить на него Constraint; автор упоминает это, но не показывает.
:::

## Таблица с выпадающими списками (препятствие 23)

**Проблема.** В каждой строке задание вроде *Select the word that starts with letter M* и выпадающий список; *Generate* меняет буквы. Для каждой строки выбрать единственное подходящее слово, затем *Submit*.

**Причина.** Буква неизвестна до выполнения, и XScan помещает отсканированный `select` вне строки.

**Решение.**

1. Module: *Generate*, *Submit*, таблица и один выпадающий список (не уникален — нормально). Сделайте `select` [встроенным контролом](/ToscaBase/ru/modules/table-controls/#встроенные-контролы-внутри-таблицы) ячейки, чтобы он существовал в каждой строке.
2. TestCase:
   - *Generate* → `X`.
   - Строка `$2` (строка 1 — заголовок). Первая ячейка → ActionMode `Verify`, значение: постоянный текст плюс `{XB[letter]}`. Динамический XBuffer одновременно верифицирует фиксированную часть и сохраняет меняющуюся букву в буфер `letter`.
   - Вторая ячейка → ActionMode `Select` (Tosca по умолчанию ставит `Verify`; измените). Вложенный список → `{B[letter]}*`, чтобы выбрать слово, начинающееся с этой буквы, не зная остального.
   - Скопируйте блок строки для строк `$3`–`$6` (пять строк данных), меняя только номер строки. Имя буфера переиспользуется; каждая строка перезаписывает его.
   - *Submit* → `X`.

`{XB[...]}` описан в [Buffers](/ToscaBase/ru/data-and-parameters/buffers/).
